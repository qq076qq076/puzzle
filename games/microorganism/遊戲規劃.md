# microorganism 遊戲規劃

## 1. 遊戲概念

`microorganism` 是一個觀察型微生物遊戲。玩家在畫面上的 180×180 格培養區放置一隻微生物，觀察它用五格身體持續爬行。第一版只提供一種黑色微生物，重點是把「延伸一格、收回一格」的身體移動規則清楚呈現出來。

第一版不加入得分、敵人、環境值或繁殖，先驗證單一微生物的身體資料與固定時間步進。

## 2. 第一版目標

- 顯示一個邏輯尺寸為 180×180 的方格培養區。
- 玩家點擊培養區後放置一隻黑色微生物。
- 微生物初始體積固定為 5 格，且五格互相連通。
- 放置後每 250 毫秒執行一次移動。
- 每次移動新增一個身體鄰近空格，再收回一個原本被身體佔用的格子，因此體積永遠維持 5 格。
- 讓玩家可以暫停、繼續與重置，方便觀察單步變化。

## 3. 畫面與操作

### 3.1 畫面

- 遊戲名稱：`microorganism`。
- 主遊戲區：180×180 邏輯格，以 Canvas 顯示；Canvas 可隨螢幕縮放，但邏輯座標永遠維持 0～179。
- 背景：米白色培養皿，顯示細緻網格與較淡的區段線，避免 32,400 格造成視覺噪音。
- 微生物：純黑色，佔用格以圓角方塊與微小連接感呈現；移動時保留短暫的灰色方向痕跡。
- 資訊面板：顯示目前狀態、體積、移動次數、更新間隔與目前座標。

### 3.2 操作

- 未放置時：點擊任一培養區位置，將微生物的五格中心放到該位置附近。
- 已放置時：點擊培養區不會新增第二隻微生物，避免第一版出現多實體規則。
- 「暫停／繼續」：停止或恢復 250 毫秒移動計時器。
- 「重置」：清除微生物與移動紀錄，回到等待放置狀態。
- 鍵盤 `Space`：切換暫停／繼續；`R`：重置。

## 4. 微生物資料設計

### 4.1 第一種微生物

| 欄位 | 設定 |
| --- | --- |
| 名稱 | 黑色微生物 |
| 識別碼 | `black-microbe` |
| 顏色 | `#111111` |
| 初始體積 | 5 格 |
| 移動間隔 | 250 毫秒 |
| 鄰近定義 | 上、下、左、右四方向 |
| 移動方式 | 隨機延伸一格，再隨機收回一格 |
| 邊界行為 | 只從培養區內的合法候選格選擇；沒有候選格時保持原狀 |

微生物的身體以 `Set<cellIndex>` 保存。`cellIndex = y * 180 + x`，因此不需要為 32,400 格建立大量 DOM 元素，只在 Canvas 上渲染。

### 4.2 初始五格形狀

玩家點擊位置會先轉換為邏輯座標 `(x, y)`，再嘗試放置十字形：

```text
    (x, y-1)
(x-1,y) (x,y) (x+1,y)
    (x, y+1)
```

如果點擊位置太靠近邊界，十字形會平移到最近的合法位置；若仍無法完整放入，則不放置並提示玩家點擊更靠近中央的位置。

## 5. 250 毫秒移動規則

### 5.1 候選延伸格

每次計時器觸發時：

1. 讀取目前身體五格。
2. 取得每一格的上、下、左、右鄰近格。
3. 排除超出 0～179 邊界的格子，以及目前已被身體佔用的格子。
4. 將剩餘格子去重，形成「所有身體佔用格的鄰近空格」清單。
5. 使用等機率亂數從清單選出一格 `newCell`。

### 5.2 收回原本佔用格

為了讓身體持續保持一整塊，新增格選定後，從「與 `newCell` 四方向相鄰的原本身體格」中等機率選出一格 `oldCell` 收回：

1. 將 `newCell` 加入身體。
2. 找出目前身體中與 `newCell` 相鄰的格子。
3. 隨機移除其中一格 `oldCell`。
4. 身體體積維持 5 格，且通過連通性檢查後，新格與其餘四格仍以四方向連成一體。
5. 記錄移動次數、移動前後座標與方向，刷新畫面。

這個規則代表微生物會從身體邊緣長出一格，再把接近新生長點的尾端收回；每次移動的方向由整個身體的鄰近空格共同決定，而不是固定朝單一方向前進。若某個收回選擇會讓五格身體斷開，就排除該選擇，改從能維持整體連通的候選中隨機選擇。

### 5.3 無法移動時

- 如果所有身體鄰近格都在邊界外或不存在合法空格，本次計時不改變身體。
- 本次仍算一次更新嘗試，資訊面板顯示「等待可用鄰近格」。
- 在一般開放培養區中不會遇到此情況，保留此規則是為了日後加入障礙物或其他微生物。

## 6. 狀態與渲染

### 6.1 遊戲狀態

```js
{
  gridSize: 180,
  tickMs: 250,
  paused: false,
  microbe: {
    id: "black-microbe-1",
    color: "#111111",
    cells: Set<number>,
    steps: 0,
    placed: false
  }
}
```

狀態更新只修改微生物的 `cells` 與統計資料；畫面由同一份狀態重繪，避免視覺位置與邏輯格不同步。

### 6.2 Canvas 渲染

- Canvas 使用固定邏輯尺寸 180×180，再依 CSS 顯示尺寸計算每格像素大小。
- 背景以低透明度繪製網格；每 10 格與每 50 格增加區段線。
- 黑色微生物每格繪製成留有小間隙的圓角方塊，讓五格形狀可辨識。
- 移動後保留最近 8 次移動軌跡，軌跡透明度由新到舊遞減。
- 游標移入時顯示目前邏輯座標，方便確認 180×180 座標系。

## 7. 驗收標準

- 規格上明確顯示 180×180 格，而非以 18×18 或其他縮小邏輯格代替。
- 點擊合法位置後，畫面只出現一隻黑色微生物且正好佔用 5 格。
- 每 250 毫秒最多完成一次延伸／收回；每次完成後體積仍為 5 格。
- 新增格必須是移動前身體任一格的四方向鄰近空格。
- 收回格必須是原本身體中、且與新增格四方向相鄰的格子。
- 每次移動後，五格身體必須通過四方向連通性檢查，不得分裂成兩個以上區塊。
- 暫停後身體不再變化，繼續後恢復 250 毫秒節奏。
- 重置後畫面回到空白培養區，所有統計歸零。
- 遊戲在桌面與窄螢幕都能操作，Canvas 不應造成頁面水平溢出。

## 8. 後續擴充方向

- 新增不同顏色、不同體積與不同移動偏好的微生物。
- 加入障礙格、培養液環境與微生物互相碰撞。
- 讓玩家設定移動間隔，或以慢動作逐步檢視每次延伸／收回。
- 將移動規則抽成可配置的行為模組，方便擴充群體模擬。
