# 10｜帳號、分享與即時同步

## 1. 三種遊戲模式

| 模式 | 身份 | 可讀取 | 可修改 | 可寫入雲端 |
|---|---|---|---|---|
| 本機／匿名 | 未建立永久帳號 | 自己的本機與匿名存檔 | 可以 | 匿名存檔可以，但不能建立分享連結 |
| 正式帳號 | Email、Google 或 Facebook 登入 | 自己帳號的私人農場 | 可以 | 可以，並可啟用固定分享連結 |
| 唯讀分享 | 由 `#share={shareId}` 進入 | 單一公開農場 | 不可以 | 不可以，訪客狀態只存在記憶體 |

唯讀模式在頁面初始化時由網址 hash 決定，不會先載入瀏覽者自己的私人存檔。唯讀訪客可以拖曳、縮放、查看植物剩餘時間、設備範圍與農夫動畫，但不能收割、播種、購買、施肥、購地、配置／拆除設備、放置／拆除裝飾、匯入或重設農場。

## 2. Firebase 必要設定

遊戲使用 `games/firebase-config.js` 的 Web 設定初始化 Firebase。Web config 可以放在前端；真正的資料保護必須由 Firebase Authentication 與 Firestore Security Rules 完成。

部署前必須在 Firebase Console 完成：

1. 建立或選擇 Firebase 專案，啟用 Firestore Database。
2. 在 Authentication → Sign-in method 啟用 Anonymous，讓遊戲能建立匿名本機／雲端存檔。
3. 依要提供的登入方式啟用 Email/Password；若要顯示社群登入，另外啟用 Google、Facebook 並設定其 OAuth 參數。
4. 在 Authentication → Settings → Authorized domains 加入 GitHub Pages 的實際網域，例如 `qq076qq076.github.io`。
5. Firestore 規則只允許使用者讀寫自己的 `/users/{uid}/saves/{gameKey}` 與 `/users/{uid}/shares/{gameKey}`；`/publicShares/{shareId}` 只允許讀取合法公開文件，寫入與刪除只能由分享擁有者透過受保護流程完成。
6. 將 Firebase Web config 的六個欄位填入 `firebase-config.js`：`apiKey`、`authDomain`、`projectId`、`storageBucket`、`messagingSenderId`、`appId`。

若 Firebase 未設定或 SDK／權限失敗，遊戲仍保留本機存檔；分享按鈕會隱藏或顯示錯誤，不會把私人存檔當作公開資料。

## 3. 私人存檔資料路徑與版本

正式或匿名帳號的遊戲存檔位於：

`/users/{uid}/saves/harvest-clicker`

文件使用以下 envelope：

| 欄位 | 用途 |
|---|---|
| `version` | envelope 版本，目前為 `1` |
| `data` | Harvest Clicker Schema v4 遊戲狀態 |
| `clientCreatedAt` | 此帳號／存檔首次建立時間 |
| `clientSavedAt` | 寫入端產生的單調遞增時間 |
| `clientRevision` | 本機 checkpoint 版本 |
| `clientWriterId` | 分頁／裝置識別，用來忽略自己的回傳快照 |
| `serverRevision` | Firestore transaction 成功後的伺服器版本 |
| `serverSavedAt`、`updatedAt` | 伺服器時間戳 |

每次寫入都以 transaction 比對 `serverRevision`。若遠端版本已前進，本機寫入會被拒絕並保留最新伺服器 checkpoint，不可靜默覆蓋其他裝置的進度。

## 4. 分享連結生命週期

### 啟用

- 只有非匿名正式帳號顯示「分享農田」按鈕。
- 點擊後先把目前農場存檔，再建立或重用該帳號固定的 `shareId`。
- 私人控制文件：`/users/{uid}/shares/harvest-clicker`。
- 公開文件：`/publicShares/{shareId}`。
- 連結格式：`index.html#share={shareId}`；代碼為 20～64 字元的英數、底線或連字號。
- 產生後直接顯示網址；複製網址使用網址右側的 icon，不另提供唯讀預覽按鈕。

### 持續同步

分享啟用後，私人存檔每次成功取得新的 `serverRevision` 都會鏡像到原本的公開文件，因此同一個連結永遠指向該帳號最新狀態，而不是建立連結當下的快照。公開 `data` 內使用 `__shareSourceRevision` 防止延遲請求把公開農場倒退。

### 撤銷

- 「停止分享」會以批次刪除公開文件與私人控制文件。
- 舊連結立即失效；再次啟用會產生新的 shareId。
- 分享公開資料上限為 900 KiB，低於 Firestore 單文件 1 MiB 限制。

## 5. 跨裝置即時同步

同一正式帳號在 A、B 裝置開啟遊戲時，都監聽：

`/users/{uid}/saves/harvest-clicker`

流程如下：

1. A 裝置完成收割、購物、購地、播種、施肥、裝備、配置設備或裝飾後，先寫入 localStorage，再立即排入 Firestore 寫入。
2. B 裝置收到 `onSnapshot`，只有在 `serverRevision` 或 `clientSavedAt` 較新時才套用。
3. B 裝置沒有未同步操作時，直接載入最新狀態、重新推進離線時間並重繪畫面。
4. B 裝置有未完成雲端寫入或本機變更時，先顯示確認，讓玩家選擇載入遠端版本，或保留本機版本並以 transaction 嘗試上傳。
5. 遠端快照來自同一個 `clientWriterId` 時忽略，避免自己的寫入回來造成重繪與提示。

唯讀分享頁也監聽 `/publicShares/{shareId}`。公開資料更新時，唯讀畫面只在記憶體內套用並依目前時間推進，不會寫入瀏覽者 localStorage 或雲端。

## 6. 寫入時機與失敗行為

### 立即寫入雲端

以下操作改變金幣或玩家持有物，必須立即完成本地 checkpoint，並以 `flushCloudSave()` 優先送出：

- 收割與自動收成
- 購買／賣出工具、種子、設備、肥料與裝飾
- 購買土地
- 收回設備、放置或拆除裝飾
- 分享啟用／撤銷

### 一般寫入

設定變更、裝備工具、相機操作與純視覺狀態不需要每一幀上傳；若有需要保存的遊戲狀態，使用短暫佇列並在頁面隱藏、離開或定時備份時 flush。

Firebase 暫時不可用、權限不足或交易衝突時：

- 不丟失 localStorage checkpoint。
- 顯示雲端／分享同步錯誤提示。
- 保留可繼續遊玩的本機狀態，待下次成功連線再嘗試上傳。

## 7. 驗收清單

- 未登入時看不到分享按鈕；登入永久帳號後才出現。
- 同一帳號重複按分享不會產生新的網址。
- A 裝置種樹或收割後，B 裝置在 Firestore snapshot 到達後看到相同狀態。
- 分享連結開啟的是帳號最新公開資料，不是建立連結時的舊快照。
- 停止分享後，公開文件與舊網址都失效。
- 唯讀頁不能改變私人存檔、公開文件或訪客本機存檔。
- `serverRevision` 較舊的請求不能覆蓋較新的私人或公開資料。
