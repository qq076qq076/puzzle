# 09｜房間、走廊與地圖隨機生成規格

## 1. 文件目的

本文件定義地城地圖如何由「房間」與「走廊」組成，並規範隨機生成、連接、可玩性驗證與失敗重試。它是 `03-房間與地層產生.md` 的詳細實作規格；03 文件描述第一階段的房間進度與威脅配置，本文件描述地圖幾何與連接方式。

第一階段的目標不是生成無限大地圖，而是以固定六房流程驗證一套可重現、可通行、可擴充的地圖生成器：

```text
入口 → 房間 1 → 走廊 1 → 房間 2 → 走廊 2 → 房間 3
     → 走廊 3 → 房間 4 → 走廊 4 → 房間 5 → 走廊 5 → Boss 房 6 → 通關
```

房間內才進行主要戰鬥；走廊負責讓玩家看見門、選擇岔路並進入下一個房間。走廊不生成怪物，但會生成有預警的地刺，岔路上有 45% 機率出現寶箱。

## 2. 地圖層級與名詞

```text
FloorMap
├── RoomNode 入口
├── RoomNode 普通房 1～5
├── RoomNode Boss 房 6
└── CorridorEdge 連接相鄰 RoomNode
```

| 名詞 | 責任 | 第一階段規則 |
|---|---|---|
| `FloorMap` | 保存整張地圖的種子、節點、邊與驗證結果 | 固定 6 個房間，拓撲為單一路徑 |
| `RoomNode` | 一個可進入、封鎖、清場、領獎與離開的戰鬥空間 | 每房有一個入口與一個出口 |
| `CorridorEdge` | 連接兩個房間門口的可行走區域 | 寬度固定、無怪物，包含環狀岔路、陷阱與機率寶箱 |
| `Connector` | 房間或走廊的連接端點 | 保存方向、門位置、玩家生成點與觸發線 |
| `OccupancyGrid` | 判斷房間、走廊、牆與障礙是否重疊 | 只在生成與驗證階段使用，不在每幀重算 |

## 3. 拓撲規則

### 3.1 第一階段固定拓撲

第一階段使用線性圖，不生成會讓玩家迷路的分支：

```text
Start ─ Room1 ─ Corridor1 ─ Room2 ─ Corridor2 ─ Room3
      ─ Corridor3 ─ Room4 ─ Corridor4 ─ Room5 ─ Corridor5 ─ Boss6 ─ Exit
```

- 房間順序由 `roomIndex` 決定，不因隨機結果改變。
- 每一條 `CorridorEdge` 只有一個來源房間與一個目標房間。
- 每個普通房清場並取得獎勵後，玩家走過出口門外觸發線才進入對應走廊／下一房。
- 走廊不提供 Enter 直接跳過；玩家必須透過實際移動完成轉場。
- 走廊的入口與出口門狀態由相鄰房間控制：前一房出口開啟後，下一房入口才可進入。

### 3.2 後續拓撲擴充

後續版本才加入分支、回溯與隱藏房。拓撲資料先保留 `edges` 陣列，避免未來把線性陣列改成完全不同格式：

- 一個房間最多 3 個連接端，避免路徑選擇過多而失去戰鬥節奏。
- 主線必須由入口連到 Boss；支線不能取代主線的必要房間。
- 分支房可以是精英房、商店或寶藏房，但不在第一階段隨機生成。
- 走廊不可形成沒有出口的死胡同，除非它的終點明確標記為寶藏房或事件房。

## 4. 座標與幾何限制

### 4.1 邏輯座標

- 遊戲邏輯基準畫面為 `960×540`；房間局部座標沿用 `ROOM_BOUNDS`。
- 導航驗證使用 28 px 的邏輯格，與現有 `room-generator.js` 的路徑驗證一致。
- 美術 Tile 的實際尺寸由素材 manifest 決定；邏輯格與美術 Tile 不必一對一，但碰撞邊界必須對齊邏輯格。
- 生成完成後將房間與走廊轉為靜態牆／障礙資料，戰鬥中不再執行地圖生成。

### 4.2 房間限制

- 房間必須落在地圖邊界內，四周保留至少 1 個邏輯格的牆體與碰撞緩衝。
- 房間最小可戰鬥寬度為 8 格、高度為 6 格；Boss 房不小於 16×12 格。
- 房間之間保留至少 2 個邏輯格的外部間距，避免牆與門重疊。
- 每個房間至少有一個可行走入口區與一個可行走出口區；入口與出口不能同時被障礙物封死。
- 障礙物只能放在模板標示的插槽，不由隨機程式直接堆疊任意矩形。

### 4.3 走廊限制

- 第一階段走廊寬度為 2 個邏輯格，約 56 px，足以讓玩家通過並保留碰撞容錯。
- 走廊主線長度為 8～14 個邏輯格，每條走廊至少產生一條重新接回主線的環狀岔路。
- 房間門口與走廊中心線必須重合，門外不得出現一格寬的尖角或無法通行縫隙。
- 走廊轉彎至少保留 2×2 個邏輯格的內角空間，避免玩家卡在直角碰撞邊。
- 走廊不能穿過其他房間、障礙物或另一條走廊；需要交叉時應先判定為生成失敗並重試。
- 走廊不生成怪物或主要 Buff，但會配置 2～3 個地刺；岔路有 45% 機率生成一次性金幣或藥水寶箱。

## 5. 房間模板與走廊模板

### 5.1 房間模板

房間模板只描述幾何與插槽，不直接保存本次 Run 的怪物狀態：

```js
{
  id: "two_arenas",
  theme: "fantasy",
  footprint: { width: 24, height: 14 },
  connectors: {
    left: { x: 0, y: 7, width: 2 },
    right: { x: 24, y: 7, width: 2 },
  },
  obstacles: [],
  spawnSockets: [],
  trapSockets: [],
  rewardSocket: { x: 12, y: 7 },
  tags: ["open", "normal"],
}
```

模板應至少涵蓋以下幾何類型：

| 類型 | 目的 | 第一階段可用房間 |
|---|---|---|
| `small_square` | 開放、容易理解的起始房 | 1～2 |
| `cross_hall` | 中央交叉線與多方向接近 | 1～3 |
| `pillars` | 柱子切割視線但保留繞行 | 2～5 |
| `trap_corridor` | 房內中央窄路與陷阱節奏 | 2～4 |
| `two_arenas` | 兩個戰鬥區由窄口相連 | 3～5 |
| `machine_room` | 機械裝飾與傳送門空間 | 4～5 |
| `ring_arena` | 環形走位，適合高威脅配置 | 4～5 |
| `elite_square` | 大型開放空間，容納精英組合 | 5 |
| `boss_arena` | Boss 階段邊界與支援怪生成 | 6 |

### 5.2 走廊模板

走廊模板只負責把兩個 `Connector` 變成可行走路徑：

| 模板 | 形狀 | 適用條件 |
|---|---|---|
| `straight` | 單段直線 | 兩個門在同一水平或垂直線 |
| `elbow` | 一次 90° 轉彎 | 房間偏移不超過 8 格 |
| `dogleg` | 兩段直線、一次主轉向 | 房間上下錯位時使用 |
| `loop` | 從主線分出並重新接回 | 每條走廊固定一條，提供避開陷阱或尋找寶箱的路線選擇 |

第一階段優先使用 `straight`；若未來房間不再固定左右排列，才開放 `elbow` 與 `dogleg`。走廊形狀的選擇必須由種子決定，不能依執行時間或畫面幀數改變。

## 6. 隨機種子與命名空間

所有隨機結果使用可重現的子種子，避免房間內容變動時連帶改變地圖位置：

```text
runSeed
├── floor:0:topology
├── floor:0:layout
├── floor:0:room:0:template
├── floor:0:room:0:content
├── floor:0:corridor:0:shape
└── floor:0:corridor:0:decor
```

- `topology` 決定房間節點與邊；第一階段固定結果，但仍保留命名空間。
- `layout` 決定房間模板位置、尺寸變體與候選重試順序。
- `room:<index>:template` 只決定房間幾何模板。
- `room:<index>:content` 決定怪物、波次、陷阱與獎勵。
- `corridor:<index>:shape` 決定直線／轉彎形式與長度。
- `corridor:<index>:decor` 決定走廊裝飾，不影響碰撞與通路。
- 任何生成失敗都增加明確的 `attempt` 後綴，不使用新的系統時間亂數。

## 7. 生成流程

### 7.1 建立拓撲

1. 建立入口、普通房 1～5、Boss 房 6 的 `RoomNode`。
2. 依房間順序建立五條 `CorridorEdge`。
3. 為每個節點指定入口／出口方向；第一階段為左進右出。
4. 記錄前後節點關係，讓上一房出口能對應下一房入口。

### 7.2 放置房間

1. 依房間編號取得允許模板池與大小變體。
2. 第一房固定靠近地圖入口，Boss 房固定在主線末端。
3. 由左至右放置房間；每個候選位置先檢查房間邊界、前一房間距與連接端方向。
4. 普通房可以有少量上下偏移，但不可讓相鄰房間的走廊超出地圖邊界。
5. 房間矩形與障礙物寫入 `OccupancyGrid`，保留牆體與碰撞 padding。

### 7.3 連接走廊

1. 取來源房間出口 `Connector` 與目標房間入口 `Connector`。
2. 若兩端中心線對齊，建立 `straight` 走廊。
3. 若不對齊，依兩種正交順序建立候選：先水平後垂直、先垂直後水平。
4. 對候選路徑加上走廊寬度，檢查每一格是否越界、撞到房間內部、撞到障礙或已有走廊。
5. 選擇總長度較短且轉彎較少的候選；分數相同時由 `corridor:<index>:shape` 決定。
6. 在走廊兩端建立門、門外觸發線與相鄰房間的進入點。
7. 將走廊地板與牆資料加入地圖輸出，但不加入戰鬥生成點。

### 7.4 配置房間內容

走廊完成連接並通過幾何驗證後，才生成房間內容：

- 依房間威脅預算抽取怪物與波次。
- 從房間的 `spawnSockets` 選擇生成點，排除入口安全區與走廊端點。
- 依 `trapSockets` 放置陷阱，不能覆蓋入口、出口或唯一通路。
- 從 `rewardSocket` 建立獎勵位置；獎勵不放在走廊上。
- 第 6 房使用固定 Boss 幾何與獨立戰鬥規則，不套用普通房怪物抽取。

## 8. 地圖資料輸出

生成器輸出的資料應保留幾何、連接與內容插槽，避免把執行期敵人狀態寫入地圖：

```js
{
  runSeed: "...",
  floorIndex: 0,
  rooms: [
    {
      id: "room-1",
      roomIndex: 0,
      templateId: "small_square",
      origin: [x, y],
      bounds: [left, top, width, height],
      entry: { side: "left", door: [x, y], spawn: [x, y] },
      exit: { side: "right", door: [x, y], trigger: [x, y] },
      obstacles: [],
      sockets: { spawn: [], traps: [], reward: [x, y] },
    },
  ],
  corridors: [
    {
      id: "corridor-1",
      from: "room-1",
      to: "room-2",
      templateId: "straight",
      width: 2,
      cells: [[x, y], [x, y]],
      entryDoor: [x, y],
      exitDoor: [x, y],
    },
  ],
  validation: { valid: true, attempt: 0, checks: {} },
}
```

執行期仍可轉換成現有 `RoomScene` 需要的 `entrySide`、`entrySpawn`、`entryDoor`、`exitDoor` 與 `exitTrigger` 欄位；地圖幾何與房間內容不應依賴 Phaser Scene 才能生成或測試。

## 9. 可玩性與完整性驗證

地圖在交給場景前必須全部通過以下檢查；任何一項失敗就丟棄候選配置：

### 幾何檢查

- 所有房間與走廊都在地圖邊界內。
- 房間之間沒有未授權重疊，走廊不穿過非端點房間。
- 每條走廊的所有格子連續、寬度一致，轉角沒有單格尖角。
- 房間門、走廊與門外觸發線順序正確：房內 → 門 → 走廊 → 觸發線。
- 所有牆與障礙物都有對應碰撞資料，沒有只畫出來但可穿越的牆。

### 路徑檢查

- 從入口可以走到普通房 1，再沿每條走廊抵達 Boss 房 6。
- 每個房間入口、出口、所有獎勵點與必要戰鬥區都可由玩家抵達。
- 走廊不可被房門、障礙或封鎖狀態永久截斷。
- 路徑檢查使用與遊戲碰撞相同的 padding，不能只用中心點判定通過。

### 戰鬥檢查

- 玩家出生點與第一波生成點保持安全距離；走廊端點不算可用生成點。
- 陷阱不覆蓋入口安全區、出口門或唯一通路全部寬度。
- 清場後出口一定能打開；獎勵點不在門碰撞盒內。
- 房間至少保留 60% 可行走面積；Boss 第三階段仍有可繞行路徑。

### 重現性檢查

- 相同 `runSeed` 與相同生成版本必須得到相同房間、走廊、障礙、插槽與內容結果。
- 改變 `runSeed` 至少應有一項模板、位置、走廊形狀或內容不同。
- 不能在渲染、輸入或戰鬥更新時修改已鎖定的地圖幾何。

## 10. 失敗重試與安全備援

- 每個地圖候選最多嘗試 24 次；嘗試編號加入 `layout:attempt:<n>` 子種子。
- 重試只改變候選模板、房間偏移、走廊路徑與裝飾，不改變房間順序與 Boss 位置。
- 若 24 次仍失敗，使用已驗證的固定安全布局，並在 `validation.fallback = true` 留下紀錄。
- 安全備援不可跳過路徑驗證；固定布局也必須跑完整檢查。
- 測試輸出應保留 `runSeed`、`attempt` 與失敗檢查名稱，方便重現與修正。

## 11. 與現有程式的責任分工

| 模組 | 生成責任 |
|---|---|
| `src/data/rooms.js` | 保存房間／走廊模板、邊界、連接插槽與美術主題，不保存本次 Run 狀態 |
| `src/systems/room-generator.js` | 依種子建立 `FloorMap`、挑模板、放置房間、生成走廊並執行驗證 |
| `src/systems/room-transition.js` | 判定玩家是否越過走廊出口觸發線，不負責生成地圖 |
| `src/scenes/RoomScene.js` | 將已生成的房間幾何轉成地板、牆、門、陷阱與敵人；不在場景中抽樣地圖 |
| `src/systems/rng.js` | 提供可重現的子種子與抽樣工具 |
| `test/room-generator.test.mjs` | 測試房間、走廊、連通性、重疊、重現性與安全備援 |

實作順序建議為：先讓生成器輸出可測試的 `FloorMap`，再把走廊地板與碰撞接到 Phaser，最後才加入走廊裝飾或事件。這樣地圖錯誤可以在不啟動瀏覽器的情況下被定位。

## 12. 素材與效能規則

- 房間與走廊的地板、牆、門、傳送門與裝飾只能從使用者提供的兩套 CraftPix 素材中選用。
- 走廊不得使用程式繪製的像素牆或臨時色塊作為正式美術；純幾何圖形只可用於碰撞除錯與驗證。
- 地圖完成後以靜態 Tile／Sprite 建立，避免每幀重建牆與走廊。
- 相同模板可共用 Texture Cache；房間切換只更新位置、碰撞與插槽，不重複載入 PNG。
- 生成器的路徑與重疊檢查只在開局或房間載入時執行，不放進 60 FPS 更新迴圈。

## 13. 生成測試案例

- 固定種子可重現完整六房地圖，包含每個房間位置、走廊格子、門與觸發線。
- 多組種子能產生不同房間模板、房間偏移或走廊長度，但所有結果都通過驗證。
- 房間偏移造成直線走廊不可行時，會選擇合法的 L 型／Dogleg 候選或進入下一次重試。
- 故意讓房間重疊、走廊越界、走廊寬度不足或入口被封鎖時，驗證器會指出具體失敗原因。
- 24 次候選全部失敗時，會得到固定安全布局，且 `fallback` 記錄為真。
- 任何房間清場後，玩家都能沿開啟的出口門與走廊抵達下一房，不依賴 Enter 或隱藏傳送。
