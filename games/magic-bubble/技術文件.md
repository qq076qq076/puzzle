# 魔法氣泡（Magic Bubbles）技術文件

> 文件版本：1.0  
> 技術基準日期：2026-09-22  
> 對應規格：[遊戲規格書](./遊戲規格書.md)  
> 部署環境：Puzzle Club 靜態網站／GitHub Pages

## 一、文件目的

本文件定義《魔法氣泡》第一版的程式架構、資料模型、核心演算法、遊戲迴圈、輸入、渲染、存檔、測試與部署方式。實作時以本文件處理「怎麼做」，玩法數值與產品範圍則以遊戲規格書為準。

技術目標：

- 不依賴後端與建置工具，直接由靜態網站部署。
- 核心規則與 DOM、動畫、音效分離，可由 Node 內建測試執行。
- 同一亂數種子和同一輸入序列得到相同結果。
- 桌面與近五年中階手機維持流暢操作。
- 遊戲切到背景時安全暫停，不因累積時間造成瞬間落下。
- 與專案現有 Firebase／`PuzzleSave` 存檔機制相容。

## 二、技術選型

| 類別 | 選擇 | 理由 |
| --- | --- | --- |
| 語言 | 原生 JavaScript ES Modules（`.mjs`） | 明確相依關係，瀏覽器與 Node 測試共用 |
| 頁面 | 語意化 HTML5 | 支援鍵盤、ARIA 與靜態部署 |
| 樣式 | 原生 CSS | 使用 Grid、Custom Properties 與 Media Query |
| 棋盤渲染 | Three.js r186／WebGL 2 | 使用 GPU 批次渲染與 3D 光照材質 |
| 動畫 | Three.js transform、Points 粒子＋少量 CSS | 規則不依賴動畫事件 |
| 遊戲時鐘 | `requestAnimationFrame` ＋固定步進 | 輸入穩定，支援不同更新率 |
| 測試 | `node:test`、`node:assert/strict` | 專案已有相同慣例，無外部依賴 |
| 存檔 | `window.PuzzleSave` | 沿用本機與 Firebase 同步、衝突處理 |
| 音效 | Web Audio API／`HTMLAudioElement` | 小型音效可低延遲播放並統一控制音量 |

第一版不引入 Phaser、React 或其他 UI 框架。Three.js 固定使用 `0.186.0`，透過 import map 從同一 CDN 載入；核心規則不依賴 Three.js，因此未來更換 WebGL／WebGPU 渲染器時不需重寫玩法。

### 3.1 載入順序

為符合靜態部署並保持模組相依清楚，使用瀏覽器原生 ES Modules。Three.js 由固定版本 import map 提供，專案共用存檔仍先以 classic script 載入：

```html
<script src="../firebase-config.js"></script>
<script src="../firebase-runtime.js"></script>
<script src="../save-system.js"></script>
<script type="importmap">
  { "imports": { "three": "https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.module.js" } }
</script>
<script type="module" src="main.mjs"></script>
```

`main.mjs` 透過靜態 import 載入其餘模組；缺少相依檔案時模組載入會直接失敗，不以部分功能啟動。Three.js 的核心與 addons 若日後加入，必須使用相同版本與相同 CDN。

### 3.2 全域命名

遊戲模組不建立專案全域；只讀取既有的 `window.PuzzleSave`。執行中的遊戲、Three.js scene、renderer 與輸入控制器皆保留在 ES Module scope，不掛到 `window`。

## 四、分層架構

```text
使用者輸入
   ↓
Input Controller ───────────────┐
   ↓ command                    │
Main / Game Loop                │ pause、settings
   ↓                            │
Game Core（純邏輯）              │
   ↓ state + domain events      │
Renderer / Audio Controller ←───┘
   ↓
DOM、CSS 動畫、Web Audio

Game Core → Save Adapter → PuzzleSave → localStorage / Firebase
```

### 4.1 `core.mjs`

負責棋盤、目前氣泡組、移動、旋轉、下落、消除、重力、計分、目標、成功與失敗。不得：

- 讀寫 DOM。
- 使用 `Date.now()`、`performance.now()` 或 `Math.random()`。
- 直接播放音效。
- 讀寫瀏覽器儲存空間。
- 使用動畫完成事件推動規則。

所有時間與亂數都由呼叫端注入。

### 4.2 `main.mjs`

組合各模組，管理畫面狀態、固定步進、領域事件派送、暫停與生命週期。它是唯一可以同時呼叫 Core、Renderer、Input、Audio 與 Save Adapter 的檔案。

### 4.3 `renderer.mjs`

接收唯讀狀態與領域事件，更新 Three.js `InstancedMesh`、幽靈落點、粒子與鏡頭。HUD 仍由 `main.mjs` 更新 DOM；渲染器不得自行決定消除、落點、分數或勝負。

### 4.4 `input.mjs`

將鍵盤、Pointer Events、觸控按鈕與手勢正規化成同一組命令：

```text
MOVE_LEFT
MOVE_RIGHT
SOFT_DROP_START
SOFT_DROP_END
HARD_DROP
ROTATE_CCW
ROTATE_CW
TOGGLE_PAUSE
RESTART_REQUEST
```

### 4.5 `main.mjs` 存檔介面

將執行期 profile 轉成穩定的存檔資料，只保存永久進度與設定，不保存進行中的棋盤。

## 六、核心資料模型

### 6.1 格子編碼

棋盤使用一維陣列，索引公式：

```text
internalY = visibleY + hiddenRows
index = internalY × columns + x
visibleY = floor(index / columns) - hiddenRows
```

總長度為 `6 × 13 = 78`。格子以小型整數編碼：

| 值 | 意義 |
| ---: | --- |
| 0 | 空格 |
| 1 | 火焰紅 |
| 2 | 星光黃 |
| 3 | 森林綠 |
| 4 | 魔力藍 |
| 8 | 干擾氣泡 |

`clearing` 是解析階段的暫時標記，不寫回格子；以 `Set<number>` 或索引陣列保存。這能避免動畫狀態污染棋盤規則。

### 6.2 遊戲狀態

```js
{
  schemaVersion: 1,
  mode: "tutorial" | "stage" | "endless",
  phase: "entry" | "active" | "locking" | "resolving" |
         "paused" | "stageClear" | "gameOver",
  board: Uint8Array(78),
  activePair: null | {
    pivotX: 2,
    pivotY: 0,
    pivotColor: 1,
    satelliteColor: 3,
    rotation: 0,
    fallAccumulatorMs: 0,
    lockElapsedMs: 0,
    lockResetCount: 0
  },
  nextPairs: [
    { pivotColor: 2, satelliteColor: 2 }
  ],
  score: 0,
  chain: 0,
  maxChain: 0,
  level: 1,
  placedPairCount: 0,
  elapsedMs: 0,
  objectiveProgress: {},
  rngState: 123456789,
  previousPhase: null
}
```

`Uint8Array` 在測試與執行期使用；傳給渲染器可以直接唯讀遍歷。需要序列化除錯快照時轉成一般陣列。

### 6.3 不變條件

每次 Core API 執行完成後必須維持：

- `board.length === 78`。
- 每格只包含合法編碼。
- 棋盤中沒有懸空氣泡，除非 phase 正在 `resolving` 且尚未套用重力。
- `activePair` 只存在於 `entry`、`active` 或 `locking`。
- `activePair` 的兩顆氣泡不與棋盤已佔用格重疊。
- `rotation` 永遠是 `0～3` 的整數。
- 分數、等級、已落定組數與時間皆為非負有限數。
- `stageClear` 與 `gameOver` 不再接受棋盤操作。

開發模式提供 `assertValidState(state)`；正式環境可關閉高成本檢查，但存檔與測試仍必須使用。

## 八、狀態機

```text
createGame
   ↓
entry ──500 ms──→ active ←──────────────┐
                    │                    │
           首次無法下降                 │
                    ↓                    │
                 locking                │
              │            │             │
     可再下降／移動成功   500 ms 到期      │
              │            ↓             │
              └→ active  resolving ──────┘
                              │
                     ┌────────┴────────┐
                     ↓                 ↓
                stageClear         gameOver
```

任一可遊玩 phase 可進入 `paused`，並以 `previousPhase` 回復。`stageClear` 和 `gameOver` 不可直接回到進行中狀態，只能建立新局或返回選單。

### 8.1 `entry`

- 氣泡組已存在，但自動下降累積器不增加。
- 接受左右移動、旋轉、快速下降與硬降。
- 500 毫秒後切換為 `active`。
- 若玩家在入場期間硬降，直接落定，不再等待。

### 8.2 `active`

- 累加自動下降時間。
- 到達目前等級間隔時，嘗試向下移一格。
- 可以下降則扣除一個下降間隔；不能下降則進入 `locking`。
- 單次 step 最多執行 `maxStepsPerFrame` 次下降，防止背景恢復後跳落。

### 8.3 `locking`

- 累加 `lockElapsedMs`。
- 水平移動或旋轉成功時重設計時並增加 `lockResetCount`。
- 若操作後可以自然下降，回到 `active`。
- `lockResetCount >= 12` 時不再重設。
- 500 毫秒到期或硬降時執行 `lockPair`。

### 8.4 `resolving`

核心邏輯可一次計算完整結果，但必須輸出分段事件，讓畫面依序播放：

```text
CLEAR_FOUND
CLEAR_APPLIED
GRAVITY_APPLIED
CLEAR_FOUND（下一連鎖）
...
RESOLUTION_COMPLETE
```

`main.mjs` 依事件的建議時間排程動畫。規則結果在進入動畫前已確定，動畫被減少、跳過或中斷都不能改變分數與盤面。

## 九、時間迴圈

### 9.1 固定步進

```js
let lastNow = performance.now();
let accumulator = 0;

function frame(now) {
  const rawDelta = now - lastNow;
  lastNow = now;
  accumulator += Math.min(rawDelta, CONFIG.limits.maxFrameDeltaMs);

  let steps = 0;
  while (accumulator >= CONFIG.timing.fixedStepMs && steps < 6) {
    update(CONFIG.timing.fixedStepMs);
    accumulator -= CONFIG.timing.fixedStepMs;
    steps += 1;
  }

  if (steps === 6) accumulator = 0;
  render(accumulator / CONFIG.timing.fixedStepMs);
  requestAnimationFrame(frame);
}
```

### 9.2 暫停與背景切換

- `visibilitychange` 變成 hidden、`pagehide` 或 window blur 時呼叫 `pause("background")`。
- 暫停後仍可渲染選單，但不呼叫 Core 的時間 step。
- 回到前景時重設 `lastNow = performance.now()` 與 `accumulator = 0`。
- 玩家必須按下繼續才恢復。
- 暫停時 Input Controller 必須清除所有 held key，避免恢復後持續移動。

## 十、移動與旋轉演算法

### 10.1 氣泡組座標

旋轉向量：

```js
const ROTATION_OFFSETS = [
  { x: 0, y: -1 },
  { x: 1, y: 0 },
  { x: 0, y: 1 },
  { x: -1, y: 0 }
];
```

副氣泡座標：

```text
satelliteX = pivotX + offset.x
satelliteY = pivotY + offset.y
```

隱藏列 `y = -1` 是合法位置；小於 -1 或大於 11 均不合法。

### 10.2 碰撞檢查

`canOccupy(board, cells)` 對每格檢查：

1. `x` 在 `0～5`。
2. `y` 在 `-1～11`。
3. 對應棋盤格為 0。
4. 兩顆輸入格不重複。

### 10.3 旋轉踢牆

`tryRotate(state, direction)`：

1. 計算 `targetRotation = mod(rotation + direction, 4)`。
2. 先測試位移 `(0, 0)`。
3. 若不合法，依序測試 `(-1, 0)`、`(1, 0)`。
4. 只有當目標方向為副氣泡在主氣泡下方時，再測試 `(0, -1)`。
5. 第一個合法候選立即成立。
6. 全部失敗則狀態不變並回傳 `changed: false`。

每個候選都必須同時驗證主、副氣泡，不能只修正副氣泡。

### 10.4 幽靈落點與硬降

`getHardDropDistance` 從距離 0 開始，同時向下測試兩顆氣泡，直到下一格不合法。幽靈落點與硬降必須呼叫同一函式，避免畫面提示與實際落點不一致。

硬降流程：

1. 取得距離 `d`。
2. `pivotY += d`。
3. 增加 `2 × d` 分。
4. 立即執行 `lockPair`。

### 10.5 分離落定

`lockPair` 不直接把目前兩格寫入棋盤，而是：

1. 取得主、副氣泡的目前世界座標。
2. 依 `y` 由大到小排序；較低的氣泡先落定。
3. 每顆氣泡在自己的欄位尋找從目前位置起可到達的最下方空格。
4. 第一顆寫入棋盤後，再計算第二顆的落點。
5. 回傳每顆氣泡的 `from`、`to` 和掉落距離供動畫使用。

直向氣泡組必須保持原本上下順序；橫向氣泡組可落到不同高度。

## 十一、棋盤解析演算法

### 11.1 尋找消除群組

`findClearGroups(board)` 使用 BFS：

```text
for each index:
  若為空、干擾或 visited，略過
  建立 queue，搜尋四方向相同顏色
  若 group.length >= 4，加入 clearGroups
```

每次只配置一個長度 78 的 `Uint8Array visited`，queue 可使用預先配置的整數陣列與 head index，避免 `shift()` 造成搬移。

回傳：

```js
{
  groups: [
    { color: 1, indexes: [61, 62, 67, 68] }
  ],
  colorIndexes: [61, 62, 67, 68],
  colors: [1],
  groupSizes: [4]
}
```

### 11.2 相鄰干擾氣泡

針對所有 `colorIndexes` 檢查四方向，將值為 8 的索引加入 `Set`。干擾氣泡不能遞迴清除其他干擾氣泡，且不加入計分顆數。

### 11.3 重力

每欄獨立使用 write pointer：

```text
writeY = 11
由 y = 11 往 -1 掃描：
  遇到非空格：
    搬到 writeY
    記錄 from → to
    writeY -= 1
剩餘位置全部清空
```

重力後同欄氣泡次序不得改變。回傳 transitions 供 Renderer 播放，不以像素位置反推棋盤。

### 11.4 完整解析

`resolveBoard(board, startingChain = 0)`：

1. 搜尋可消除群組。
2. 若沒有群組，結束並回傳總分及所有步驟。
3. 連鎖數加一。
4. 計算相鄰干擾氣泡。
5. 計算本輪分數。
6. 清除彩色與干擾索引。
7. 套用重力並記錄 transitions。
8. 回到步驟 1。

回傳資料：

```js
{
  board,
  totalScore,
  finalChain,
  maxChain,
  totalColoredCleared,
  totalGarbageCleared,
  clearedByColor,
  steps: [
    {
      chain: 1,
      groups,
      colorIndexes,
      garbageIndexes,
      colors,
      score,
      gravityTransitions
    }
  ]
}
```

## 十二、計分實作

```js
function calculateClearScore({ chain, groupSizes, colorCount }) {
  const coloredCount = groupSizes.reduce((sum, size) => sum + size, 0);
  const chainBonus = CHAIN_BONUS[Math.min(chain, CHAIN_BONUS.length - 1)];
  const groupBonus = groupSizes.reduce((sum, size) => sum + groupBonusFor(size), 0);
  const colorBonus = COLOR_BONUS[colorCount] || 0;
  const multiplier = Math.min(999, Math.max(1, chainBonus + groupBonus + colorBonus));
  return 10 * coloredCount * multiplier;
}
```

注意：

- 第 1 連鎖的連鎖加成為 0，但總倍率下限為 1。
- 干擾氣泡不加入 `coloredCount`。
- 同輪不同群組分別計算群組加成後相加。
- 一次解析的各輪分數分別計算再加總，不能先合併顆數。
- 所有分數使用安全整數；若未來可能超過 `Number.MAX_SAFE_INTEGER`，顯示層可縮寫，但第一版不得改用浮點科學記號寫入存檔。

## 十三、亂數系統

禁止 Core 使用 `Math.random()`。第一版採 `mulberry32` 或等價的 32 位元確定性 PRNG：

```js
const rng = createRng(seed);
const color = rng.nextInt(1, activeColorCount);
```

要求：

- `seed` 轉成 unsigned 32-bit integer。
- PRNG 狀態可讀取、複製與恢復。
- 建立新局時由 `crypto.getRandomValues` 產生種子；不可用時才降級到時間值。
- 教學與測試直接指定固定種子或固定 pair queue。
- `nextPairs` 至少保持一組；消耗目前組後立即補一組。
- 關卡若使用三色，只能從該關允許的顏色集合取樣。

## 十四、輸入系統

### 14.1 鍵盤狀態

Input Controller 保存：

```js
{
  held: Set<string>,
  horizontalDirection: -1 | 0 | 1,
  horizontalHeldMs: 0,
  repeatAccumulatorMs: 0,
  softDropHeld: false
}
```

- 左右鍵首次按下立刻發出一次命令。
- 持續 160 毫秒後啟動 DAS，每 65 毫秒發出 ARR 重複。
- 左右同時按下時，以最後按下的方向為主；釋放後若另一鍵仍按住，立刻切回。
- 旋轉與硬降忽略瀏覽器 `event.repeat`，每次實體按下只觸發一次。
- phase 非可操作狀態時丟棄棋盤命令，不排隊到動畫結束後執行。

### 14.2 Pointer 與手勢

- 使用 Pointer Events 統一滑鼠、觸控筆與觸控。
- `pointerdown` 後呼叫 `setPointerCapture`。
- 每累積 28 CSS px 水平位移送出一次左右移動，可連續跨格。
- 垂直向下位移超過 18 px 時啟動 soft drop；釋放時送出結束。
- 120 ms 內向下超過 70 px 視為 hard drop，只能觸發一次。
- 點擊位移小於 10 px 且時間小於 260 ms 時順時針旋轉。
- 手勢開始於按鈕或對話框時不得傳給棋盤。

### 14.3 防止頁面捲動

只在遊戲區取得互動焦點且命令有效時呼叫 `preventDefault()`。CSS 棋盤區使用 `touch-action: none`，控制按鈕使用 `touch-action: manipulation`；頁面其他區域仍可正常捲動。

## 十五、Three.js 渲染系統

### 15.1 Scene 分層

```text
Scene
├── HemisphereLight / DirectionalLight / PointLight
├── BoardGroup
│   ├── 棋盤背板與外框 Mesh
│   ├── 72 格底槽 InstancedMesh
│   ├── 5 組實體氣泡 InstancedMesh
│   ├── 5 組符號 InstancedMesh
│   └── 5 組幽靈落點 InstancedMesh
├── 魔法環 Mesh
├── 背景星點 Points
└── 消除粒子 Points
```

一般氣泡依四種顏色分桶，封印石獨立一桶。每桶共用 geometry 與 material，以 `InstancedMesh` 批次繪製；符號也依類型批次繪製，避免每顆氣泡建立獨立 Mesh。消除粒子使用固定上限的單一 `Points` buffer。

### 15.2 座標與相機

使用 OrthographicCamera，棋盤中心為世界座標原點：

```text
worldX = x - 2.5
worldY = 5.5 - y
worldZ = 0
```

可見棋盤涵蓋 X `-2.5～2.5`、Y `-5.5～5.5`；隱藏列位於 Y `6.5`。ResizeObserver 依 canvas 容器比例更新相機左右邊界，垂直視野維持 14.3 世界單位，因此旋轉裝置不會改變規則座標。

### 15.3 批次更新

Renderer 只有在 Core 狀態改變時重建 instance matrix：

- 掃描 78 格棋盤並按類型分桶。
- 將活動氣泡加入對應實體桶。
- 使用 Core 的 `getHardDropDistance` 建立幽靈落點。
- 逐桶呼叫 `setMatrixAt`，設定 `count`，最後一次標記 `instanceMatrix.needsUpdate`。

每個動畫 frame 只更新背景星點、魔法環、粒子 buffer 與呼叫 `renderer.render`，不建立新的 Mesh、Geometry、Material 或 DOM 節點。

### 15.4 動畫協定

領域事件與動畫對應：

| 事件 | 動畫 |
| --- | --- |
| `PAIR_MOVED` | 更新活動 instance matrix、短促音效 |
| `PAIR_ROTATED` | 更新活動 instance matrix、旋轉音效 |
| `PAIR_LOCKED` | 落定音效與棋盤 instance 更新 |
| `CHAIN_STEP` | Points 爆裂、連鎖文字與音高上升 |
| `GAME_OVER` | 頂部封印碎裂與盤面淡出 |

`prefers-reduced-motion: reduce` 或遊戲設定開啟時，所有非必要動畫縮短至 0～80 ms，移除鏡頭震動、縮放彈跳與大量粒子。

### 15.5 ARIA

WebGL canvas 使用單一可聚焦元素與完整操作標籤，不建立 72 個可聚焦格。另以 `aria-live="polite"` 宣告：

- 新氣泡組顏色。
- 連鎖數與得分。
- 目標完成。
- 危險、暫停、過關與失敗。

每秒最多更新 live region 兩次，避免快速操作時洗版。

## 十六、音效系統

`audio.mjs` 提供：

```js
{
  unlock(),
  play(name, options),
  setMusicVolume(value),
  setSfxVolume(value),
  setMuted(value),
  setDangerState(active),
  suspend(),
  resume(),
  destroy()
}
```

- 第一次使用者手勢後才建立或 resume `AudioContext`。
- 音樂與音效使用獨立 gain node。
- 同名移動音效最短間隔 35 ms。
- 危險警示最短間隔 1200 ms。
- 連鎖音高由事件中的 chain 決定，最高值 clamp，不能無限升高。
- 暫停與背景隱藏時 suspend；恢復需玩家手勢。
- 音訊載入失敗不得阻止遊戲。

## 十七、關卡資料

`levels.mjs` 保存不可變資料：

```js
{
  id: "stage-01",
  chapter: 1,
  title: "第一個咒語",
  colors: [1, 2, 3],
  startLevel: 1,
  initialBoard: [],
  fixedPairs: [],
  objective: {
    type: "clearColor",
    color: 1,
    amount: 12
  },
  starScores: [0, 2500, 5000],
  timeLimitMs: null,
  tutorialSteps: []
}
```

### 17.1 初始盤面格式

使用可讀的 13 行字串，第一行代表隱藏列：

```js
initialBoard: [
  "......",
  "......",
  "......",
  "......",
  "......",
  "......",
  "......",
  "......",
  "......",
  "......",
  "..R...",
  ".RRG..",
  "##G##."
]
```

字元對應：`.` 空、`R` 紅、`Y` 黃、`G` 綠、`B` 藍、`#` 干擾。載入時必須驗證行數、欄數、字元、生成格與是否存在不應在開局自動消除的群組。

### 17.2 目標更新

Core 只接收解析摘要更新目標：

- `score`：取目前總分。
- `clearColor`：累加 `clearedByColor[color]`。
- `chain`：取 `max(previous, finalChain)`。
- `clearGarbage`：累加 `totalGarbageCleared` 或讀取剩餘干擾數。
- `survive`：以 active gameplay 的 `elapsedMs` 判斷。

### 18.2 `PuzzleSave` 設定

```js
window.PuzzleSave.create({
  key: "magic-bubble",
  autoRestore: true,
  fresh: createDefaultProfile,
  restore: restoreProfile,
  validate: validateProfile,
  hasProgress: hasMeaningfulProgress,
  getState: serializeProfile

```

實際 localStorage key 由共用系統產生為：

```text
puzzle-club-save:magic-bubble:v1
```

不得同時另外維護第二份 `magic-bubble-save-v1`，避免資料來源衝突。`autoRestore: true` 避免玩家每次只因設定存在就看到「繼續上次遊戲」對話框。

### 18.3 驗證與正規化

- 所有數值必須是有限非負數，再依合理上限 clamp。
- 關卡 ID 必須存在於 `MagicBubbleLevels`。
- 星等限制為整數 `0～3`。
- 音量限制為 `0～1`。
- 未知欄位忽略；缺少欄位補預設值。
- 較舊版本先 migration，再 validate。
- 損壞資料不得丟出到主程式；保留可辨識設定後重建其餘資料。

## 二十、錯誤處理與記錄

### 20.1 可恢復錯誤

- 音訊載入失敗：停用該音效，遊戲繼續。
- localStorage 或 Firebase 失敗：維持記憶體內進度，顯示一次非阻塞提示。
- haptic 不支援：直接忽略。
- 圖片載入失敗：使用 CSS 顏色、符號與輪廓 fallback。

### 20.2 不可恢復錯誤

核心依賴缺失、關卡資料無效或狀態不變條件被破壞時：

1. 停止遊戲迴圈。
2. 不覆寫既有存檔。
3. 在遊戲區顯示「遊戲載入失敗，請重新整理」。
4. `console.error` 輸出模組、phase 與錯誤 stack，但不得輸出 Firebase token 或個人資料。

正式環境不顯示 stack 給玩家。

## 二十一、測試策略

### 21.1 單元測試

核心測試直接 import ES Module，不載入 Three.js 或 DOM：

```js
import test from "node:test";
import assert from "node:assert/strict";

import { findClearGroups } from "../core.mjs";
```

最低覆蓋案例：

- 直線、L、T、方形與大於四顆群組。
- 斜向相鄰不消除。
- 同輪同色分離群組與多色群組。
- 干擾氣泡四向消除、斜向保留、不連鎖擴散。
- 每欄重力順序與 transition。
- 1、2、3、5 連鎖固定盤面。
- 每一個計分倍率邊界。
- 四方向旋轉、左右踢牆、向上修正與完全失敗。
- 橫向分離落定與直向順序。
- soft drop、hard drop、lock delay 和 12 次重設上限。
- 生成格失敗時機。
- 關卡目標與星等。
- 相同 seed 的序列相同，不同 seed 大多不同。
- 存檔缺欄、未知欄、損壞值與版本 migration。

### 21.2 整合測試

以命令序列而非真實時間驅動：

```js
const result = runScenario({
  seed: 1234,
  commands: [
    [0, "MOVE_LEFT"],
    [16, "ROTATE_CW"],
    [32, "HARD_DROP"]
  ]
});
```

驗證最終棋盤、分數、連鎖、事件順序與 phase。Scenario fixture 應以短小 JSON 保存，不保存渲染像素。

### 21.3 手動驗收

- Chrome、Safari、Firefox 最新兩個主要版本。
- iOS Safari 與 Android Chrome 直向模式。
- 320、375、768、1280 CSS px 寬度。
- 鍵盤 only、觸控 only、色弱模式、減少動態效果。
- 切換分頁、旋轉裝置、快速重複暫停、音訊被瀏覽器封鎖。
- 離線啟動、localStorage 被封鎖與 Firebase 不可用。

### 21.4 建議執行命令

```bash
node --test games/magic-bubble/test/*.test.mjs
```

若 zsh 不展開空 glob，第一次建立測試前可指定單一測試檔；CI 中必須確保至少存在一個匹配檔案。

## 二十二、效能預算與量測

| 指標 | 目標 |
| --- | --- |
| 一般遊戲更新 | 桌面 < 2 ms／frame；手機 < 4 ms／frame |
| 棋盤解析 | < 1 ms，一次最多 78 格 |
| WebGL draw calls | 一般盤面 ≤ 18 |
| 粒子 Points | 桌面 ≤ 220；手機可降至 100 |
| 長任務 | 正常遊玩不得出現 > 50 ms |
| 壓縮後初始資源 | < 8 MB |
| 目標 FPS | 60；低階裝置最低可操作 30 |

量測時使用至少一個填滿 70 格、同輪四組消除、五連鎖的壓力盤面。不得只測空棋盤。

## 二十三、安全與內容限制

- 所有關卡文字以 `textContent` 插入，不用未清理的 `innerHTML`。
- 固定關卡資料也必須通過 schema 驗證，避免錯誤資料破壞 DOM class 或 CSS variable。
- 不載入未核准的第三方 script、字型或追蹤器。
- 不保存姓名、裝置識別碼或其他個人資料。
- 分享分數功能若日後加入，只能將數值轉成文字，不得將存檔 JSON 放入 URL。
- 素材檔名與授權資訊需記錄於 `assets/README.md`。
