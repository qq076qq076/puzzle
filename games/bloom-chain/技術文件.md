# 花漾連鎖（Bloomshift）技術文件

> 文件版本：1.0  
> 技術基準日期：2026-09-24  
> 對應規格：[遊戲規格書](./遊戲規格書.md)  
> 部署環境：Puzzle Club 靜態網站／GitHub Pages

## 一、文件目的

本文件定義《花漾連鎖》第一版的程式結構、純邏輯核心、盤面演算法、遊戲時鐘、輸入、Three.js 渲染、存檔與部署方式。玩法條件與數值以遊戲規格書為準；本文處理「如何實作」。

技術目標：

- 使用 Three.js 顯示花瓣盤面、消除動畫與輕量 2.5D 特效。
- 不依賴後端或建置工具，可由專案靜態網站部署。
- 盤面規則不依賴 Three.js、DOM、瀏覽器時間或 `Math.random()`。
- 相同亂數種子與相同輸入序列可重現相同遊戲結果。
- 桌面與手機共用一份棋盤邏輯；DOM 承載選單、HUD 與無障礙資訊。
- 暫停、背景分頁與低更新率不會造成盤面突然連升或連續補算。

## 二、技術選型

| 類別 | 選擇 | 理由 |
| --- | --- | --- |
| 語言 | 原生 JavaScript ES Modules（`.mjs`） | 瀏覽器可直接載入，核心亦可由 Node 測試。 |
| 棋盤渲染 | Three.js `0.186.0`／WebGL 2 | 與專案《魔法氣泡》共用已採用的 Three.js 版本與載入模式。 |
| 相機 | `THREE.OrthographicCamera` | 棋盤是固定方格，不需要透視變形；螢幕比例變更不改變格子規則。 |
| 面板批次 | `THREE.InstancedMesh` | 重複花瓣、符號和格線可共用幾何並降低 draw call。 |
| 特效 | Three.js transform、受限 `THREE.Points` 粒子 | 支援綻放、落下與升盤回饋，不引進額外後處理依賴。 |
| 遊戲時鐘 | `requestAnimationFrame`＋固定 60 Hz 步進 | 讓不同螢幕更新率下的規則一致。 |
| UI | 語意化 HTML5＋原生 CSS | 選單、計時、按鈕與螢幕閱讀器資訊保留 DOM 語意。 |
| 測試 | Node.js `node:test`、`node:assert/strict` | 核心不載入 Three.js，可直接測試規則與固定亂數案例。 |
| 存檔 | `window.PuzzleSave` | 沿用 Puzzle Club 本機存檔與 Firebase 同步入口。 |

第一版不加入 Phaser、React、Vue 或 WebGL 後處理套件。Three.js 固定由 import map 載入 `0.186.0`；Three.js 及其 addons 如有新增，必須使用相同版號與 CDN。遊戲規則不能由渲染器或動畫完成回呼推進。

## 四、載入與模組邊界

`index.html` 使用瀏覽器原生 ES Modules，Three.js import map 固定版本：

```html
<script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.186.0/build/three.module.js"
    }
  }
</script>
<script src="../firebase-config.js"></script>
<script src="../firebase-runtime.js"></script>
<script src="../save-system.js"></script>
<script type="module" src="main.mjs"></script>
```

頁面中只允許 `main.mjs` 建立遊戲實例及協調模組。Scene、核心狀態與控制器保留在 ES Module scope，不掛到 `window`。共用全域僅讀取現有的 `window.PuzzleSave`。

```text
DOM／Pointer Events
       ↓ normalized command
Input Controller → Main／固定步進 → Game Core
                           │             │
                           │             └─ state snapshot + domain events
                           ├─ Renderer ←────────────┘
                           ├─ DOM HUD／Accessibility
                           ├─ Audio Controller
                           └─ Save Adapter → PuzzleSave → localStorage／Firebase
```

### 4.1 模組責任

- `core.mjs`：盤面、選取位置、交換、匹配、連鎖、落下、上升佇列、分數、時間與勝負狀態。只接受資料和明確時間增量。
- `main.mjs`：初始化頁面、建立各控制器、執行固定步進、分派命令及事件、管理主選單／暫停／結果畫面。
- `renderer.mjs`：把唯讀盤面快照和領域事件轉為 Three.js instance transform 與粒子；不決定匹配、分數或結果。
- `input.mjs`：將鍵盤、滑鼠和觸控轉成固定命令；不直接修改棋盤。
- `save-adapter.mjs`：建立預設 profile、驗證和正規化存檔、呼叫 `PuzzleSave`。
- `audio.mjs`：管理音量、靜音、音訊生命週期與事件音效；音訊失敗不影響核心。
- DOM UI：顯示模式、分數、倒數、連鎖提示、警示與結果；不在 HUD 中複製一份可寫盤面狀態。

## 五、設定與資料模型

`config.mjs` 為玩法數值單一來源。規格書有明訂的數值不可只在 renderer 或 CSS 中另設一份。

```js
export const BOARD = Object.freeze({ columns: 6, rows: 12, startRows: 6 });

export const CELL = Object.freeze({
  empty: 0,
  rose: 1,
  gold: 2,
  leaf: 3,
  lake: 4,
  violet: 5
});

export const TIMING = Object.freeze({
  fixedStepMs: 1000 / 60,
  settleMs: 100,
  clearMs: 320,
  fallPerRowMs: 55,
  maxFallMs: 220,
  initialRiseMs: 9000,
  riseStepEveryMs: 45000,
  riseStepMs: 400,
  minRiseMs: 3800,
  maxQueuedRiseRows: 2,
  maxActiveSwapsPerWave: 4,
  timeAttackMs: 120000,
  maxFrameDeltaMs: 100,
  maxStepsPerFrame: 6
});
```

### 5.1 盤面座標

- 一維索引為 `index = y * BOARD.columns + x`。
- `x` 為 `0～5`，`y` 為 `0～11`；`y = 0` 是最上列。
- 盤面資料用固定長度的 `Uint8Array(72)`；`0` 表示空格，`1～5` 表示五種花瓣。
- 為讓 renderer 在動畫中追蹤單顆面板，另以 `Int32Array(72)` 保存執行期 `tileId`；空格的 ID 為 `0`。ID 不參與匹配、計分或存檔。
- 游標保存為 `{ x, y }`，其中 `x` 是選取框左側格，範圍為 `0～4`。

### 5.2 遊戲狀態

```js
{
  schemaVersion: 1,
  mode: "endless" | "timeAttack",
  phase: "playing" | "paused" | "complete" | "gameOver",
  board: Uint8Array(72),
  tileIds: Int32Array(72),
  cursor: { x: 0, y: 0 },
  resolvePhase: "idle" | "settling" | "clearing" | "falling",
  clearCells: [],
  clearTileIds: [],
  pendingClearGroups: [],
  busyCells: [],
  wave: 0,
  activeSwapsThisWave: 0,
  score: 0,
  maxChain: 0,
  elapsedMs: 0,
  riseElapsedMs: 0,
  queuedRiseRows: 0,
  timeAttackRemainingMs: 120000,
  rngState: 1,
  nextTileId: 1
}
```

狀態只由核心函式修改。Renderer 取得拷貝或唯讀 snapshot；不可保留並改寫核心陣列。`tileIds` 是視覺動畫識別用途，存檔只包含最高分、連鎖紀錄與設定。

### 5.3 領域事件

核心回傳事件陣列供 renderer、DOM 和 audio 消費，主要事件如下：

```text
GAME_STARTED, CURSOR_MOVED, PANELS_SWAPPED,
CLEAR_STARTED, CLEAR_FINISHED, GRAVITY_STARTED, GRAVITY_FINISHED,
CHAIN_UPDATED, SCORE_UPDATED, BOARD_RAISED, RISE_WARNING,
TIME_UPDATED, GAME_PAUSED, GAME_RESUMED, GAME_COMPLETE, GAME_OVER
```

事件至少包含所需盤面索引、面板類型或 tile ID。事件不可攜帶 DOM 節點、Mesh 或 Three.js Vector 物件。

## 六、核心 API 與狀態持有

```js
createGame({ mode, seed })                 // 建立新狀態及初始事件
applyCommand(state, command)               // 套用一個輸入命令並回傳事件
stepGame(state, stepMs)                    // 推進核心時間並回傳事件
findMatches(board, ignoredTileIds = [])    // 回傳 tile ID 群組及消除索引
applyGravity(state)                        // 壓實每欄並回傳 tile transitions
getSnapshot(state)                         // 建立 renderer 可用的唯讀快照
createDefaultProfile()                     // 建立分數與設定 profile
normalizeProfile(saved)                    // migration、驗證、補預設與 clamp
```

核心採單一 writer 的可變狀態模型：`main.mjs` 是唯一呼叫 `applyCommand` 與 `stepGame` 的模組；每次呼叫完成後發出事件並標記 snapshot 版本。不得由動畫 callback 改寫盤面，也不得由 UI event handler 直接寫入 `state.board`。

核心禁止使用：

- `document`、`window`、DOM、Three.js 與 Web Audio 類別。
- `Date.now()`、`performance.now()` 或未注入的系統時鐘。
- `Math.random()`。
- CSS／Tween 完成回呼作為清除、升盤或連鎖判斷依據。

### 6.1 固定步進遊戲迴圈

`main.mjs` 使用 `requestAnimationFrame` 維持遊戲時鐘；系統時間只用於計算本次畫面間隔，不傳進核心當作絕對時間：

```js
frameDelta = Math.min(now - lastNow, TIMING.maxFrameDeltaMs);
accumulator += frameDelta;
let steps = 0;
while (accumulator >= TIMING.fixedStepMs && steps < TIMING.maxStepsPerFrame) {
  dispatch(stepGame(state, TIMING.fixedStepMs));
  accumulator -= TIMING.fixedStepMs;
  steps += 1;
}
renderer.render(getSnapshot(state), accumulator / TIMING.fixedStepMs);
```

每個影格最多執行 `maxStepsPerFrame` 次核心步進。分頁轉入 hidden 時先暫停遊戲、清空 accumulator 與按住輸入；回前景不計入 hidden 時間，等待玩家明確繼續。

## 七、遊戲狀態與盤面解析

### 7.1 應用程式畫面狀態

主畫面的狀態由 `main.mjs` 管理：

- `menu`：尚未開始。
- `playing`：可輸入，核心正常前進。
- `paused`：不呼叫遊戲步進，保留盤面。
- `result`：無盡失敗或限時結束後顯示紀錄。
- `error`：Three.js、canvas 或必要模組無法啟動時顯示可讀取的錯誤面板。

核心內另以 `resolvePhase` 表示盤面是否正在等待交換判定、消除或下落，不用應用程式畫面狀態取代盤面流程。

### 7.2 一次消除與連鎖處理

1. `idle` 期間成功交換後，進入 `settling` 並等待 `settleMs`；settling 期間不接受第二次交換。
2. `findMatches` 檢查水平、垂直的同色連續面板。沒有匹配時回到 `idle`，交換不回復。
3. 找到匹配時記錄本輪 `clearCells`，第一輪設 `wave = 1`，啟動 `CLEAR_STARTED` 並進入 `clearing`。
4. 消除動畫期間不允許交換 `clearTileIds` 或已列入 `pendingClearGroups` 的面板；其他位置可操作。掃描交換後的盤面，將新匹配群組記錄為 tile ID 群組並以待處理亮光提示。
5. `clearMs` 到期後移除本輪面板、即時計算每欄重力結果並產生 `{ tileId, from, to }` transitions。
6. 若有面板位移，進入 `falling`；`busyCells` 包含移動面板的來源與目的格，該等格不可作為交換目標。其他格仍可操作。
7. 落下計時結束，或確認不需要下落時，掃描完整盤面並將重力新形成的群組合併到 `pendingClearGroups`。若有任何待處理群組，依 tile ID 找出它們目前所在格並開始下一輪消除；沒有時回到 `idle`。
8. 重力和盤面升高造成的匹配也在該次穩定檢查中判定。

`pendingClearGroups` 是 `Array<Array<tileId>>`。它保存解析期間已成功接出的消除，不保存格子索引；因此即使面板隨後下落改變位置，下一輪仍能清除相同的面板。群組重疊時依共同 tile ID 合併，避免同一面板重複計分。清除待處理群組時依當下位置重建 `clearCells`，不再要求面板維持直線。

核心的 clear、fall 計時與 renderer 動畫共用 `TIMING` 常數；規則不等待 Three.js tween 結束。交換期間產生的群組立即鎖定並列入待處理，避免下一次操作移動已經成立的連鎖。

### 7.3 同時消除組數

- 先逐列和逐欄掃描長度至少三格的連線，標記所有命中索引。
- 交疊格只標記一次；消除群組以 tile ID 保存，方便落下後追蹤。
- 以四方向鄰接的命中格分群；相交或相連的消除線合併為一組，分離群組各自計數。
- 第一輪消除視為第 1 連鎖；同一穩定檢查中的多組只算同一層連鎖。

## 八、落下、交換與可操作窗口

### 8.1 重力

- 每欄從底部向上讀取非空面板，維持相對上下順序並壓至最低空格。
- `applyGravity` 同步搬動面板類型與 `tileId`，不可在不同欄之間移動。
- 回傳移動前後索引、面板類型與 ID 供 renderer 播放 tween。
- 動畫 duration 為 `min(maxFallMs, 最大下落格數 × fallPerRowMs)`；核心計時到期前 renderer 不得刪除面板。

### 8.2 水平交換

- `SWAP` 只交換游標 `{x,y}` 與 `{x+1,y}`，可包含空格；兩格皆空時拒絕。
- 交換類型與 tile ID 一起交換；成功後不因無匹配而復原。
- settling 期間不接受第二次交換。消除期間或落下期間，若選取格命中 `clearTileIds`、待處理群組或 `busyCells`，拒絕該命令並回傳 `INPUT_BLOCKED`。
- `clearing` 期間每輪最多接受 4 次成功交換。計數在下一輪開始時歸零；其他相位不套用此上限。
- 消除期間每次成功交換後掃描未鎖定面板，新增匹配群組的 tile ID 到 `pendingClearGroups`。落下期間若操作形成匹配，也立即加入待處理群組。
- 穩定點再掃描一次全盤，將重力產生的匹配併入待處理群組；不在動畫 callback 中檢查。

## 九、盤面上升與模式時鐘

### 9.1 上升間隔

依據已遊玩毫秒數計算間隔，避免每 45 秒建立重複 timer：

```js
riseIntervalMs = Math.max(
  TIMING.minRiseMs,
  TIMING.initialRiseMs
    - Math.floor(elapsedMs / TIMING.riseStepEveryMs) * TIMING.riseStepMs
);
```

間隔從 9 秒開始，每 45 秒縮短 0.4 秒，最短 3.8 秒，與遊戲規格一致。遊戲計時器在消除與落下期間持續前進。

### 9.2 升盤佇列

- 上升計時到期但盤面仍在解析時，`queuedRiseRows` 增加 1，最多到 2。
- 佇列到 2 時暫停累積上升時間；不再追加或丟棄超額升盤。
- 盤面穩定後一次執行一列升盤，之後重新檢查匹配。若新列造成消除，先完成該次解析再處理下一個待升列。
- 待升列清空後重設上升計時並繼續倒數。
- `BOARD_RAISED` 事件提供插入的底列和位移映射，renderer 可將既有面板平滑上移一格。

### 9.3 失敗及限時完成

- 升盤前保存原頂列；若其中有任何面板，該列將被推出可見盤面，立即進入 `gameOver`，不覆寫或環繞資料。
- 若原頂列全空，所有列上移一格，底列加入六個新面板，再掃描可能形成的匹配。
- 限時模式以 `timeAttackRemainingMs` 倒數；到 0 時進入 `complete` 並停止後續升盤與輸入。
- 先發生的失敗或倒數歸零先決定結果，不能同一固定步進同時更新已結束的盤面。
- `paused`、`menu`、`result` 和 `error` 狀態不推進任何遊戲計時。

## 十、分數計算

核心在每輪開始清除前計算本輪面板數、分離消除組數與 `wave`，公式需與遊戲規格一致：

```text
base = 本輪消除面板數 × 10
chainBonus = base × (連鎖層數 - 1) × 0.5
simultaneousBonus = max(0, 本輪分離消除組數 - 1) × 50
roundScore = base + chainBonus + simultaneousBonus
```

- 使用整數分數；目前公式產生半分時以四捨五入取整。
- 分數更新只在核心完成一次，DOM 與 renderer 不重複計算。
- 無盡模式存活時間是升盤和敗北依據；消除不直接替時間加值。
- 最高分與最高連鎖只於回合結束時計入 profile，當局 HUD 即時顯示核心狀態。

## 十一、亂數與初始盤面

`rng.mjs` 提供純函式 PRNG，所有抽樣都更新 `rngState` 並回傳新狀態和值。使用固定 32 位元整數演算法（例如 xorshift32），將零 seed 正規化為固定非零種子。

### 11.1 起始盤面

- 建立 72 格空盤，僅填入最底 6 列。
- 依固定 seed 生成面板，避免初始盤直接存在橫向或縱向三連。
- 檢查盤面至少有兩種有效交換；不足時從同一 PRNG 狀態重生，最多嘗試 64 次。
- 超過重試上限時使用固定、已知可操作且無既有消除的安全盤面，避免不確定迴圈。

### 11.2 新底列

- 依欄位由左至右抽取五種面板。
- 抽取當下避免生成橫向三連；縱向三連可在列升入盤面後出現，並由正常解析流程處理。
- 亂數種子與盤面一起供 `createGame` 初始化；不使用時間戳直接產生遊戲邏輯亂數。

## 十二、輸入系統

`input.mjs` 將裝置事件轉為下列命令：

```text
MOVE_CURSOR(dx, dy)
SET_CURSOR(x, y)
SWAP
PAUSE
RESTART_REQUEST
```

### 12.1 鍵盤

| 操作 | 按鍵 |
| --- | --- |
| 移動游標 | 方向鍵或 `WASD` |
| 交換游標框內的面板 | `Space` 或 `Enter` |
| 暫停／繼續 | `Esc` 或 `P` |

方向鍵需在棋盤 canvas 聚焦時阻止頁面捲動。按住方向鍵使用 160 ms 首次重複延遲、每 90 ms 移動一格；核心仍負責欄列邊界檢查。

### 12.2 滑鼠與觸控

- 以 Pointer Events 統一滑鼠與觸控，不註冊重複的 `touchstart` 邏輯。
- `THREE.Raycaster` 僅用於盤面點擊拾取；不在每一影格做 raycast。
- 點擊一格時設定游標；若點到最右欄，將選取左移一格，確保游標不超過 `x = 4`。
- 再次點擊游標框任一格送出 `SWAP`。
- 水平滑過一格送出對應方向的 `SWAP`；一個 pointer gesture 最多觸發一個 swap。
- 觸控介面不依賴 hover，面板外的暫停按鈕等主要控制區至少為 44 × 44 CSS px。
- `pointercancel`、視窗失焦或暫停時清除按住方向等輸入狀態。

## 十三、Three.js 場景與渲染

### 13.1 場景樹

```text
THREE.Scene
├── Ambient / Hemisphere Light
├── BackgroundGroup
│   ├── GardenBackdrop
│   └── DecorativeLeaves (static, low count)
├── BoardGroup
│   ├── BoardBackplate
│   ├── CellBase InstancedMesh
│   ├── PetalPanels[5] InstancedMesh
│   ├── PanelSymbols[5] InstancedMesh
│   ├── CursorFrame
│   └── DangerFrame
└── EffectGroup
    ├── ClearParticles (pooled Points)
    └── RiseParticles (pooled Points)
```

Five 種花瓣分別使用辨識度明確的程式化 `ShapeGeometry`／`ExtrudeGeometry` 輕量造型及符號幾何。每種面板共用一份 geometry 和 material；每個盤面最多 72 顆，不為格子建立獨立 DOM 或無上限 Mesh。

### 13.2 座標與相機

- 使用 `OrthographicCamera`，世界棋盤中心為 `(0, 0, 0)`。
- 格子邊長由 `CELL_SIZE` 單一常數定義：`worldX = (x - 2.5) * CELL_SIZE`、`worldY = (5.5 - y) * CELL_SIZE`。
- 所有格子都保持正方形。依 canvas 寬高比調整相機可視範圍並保留安全邊界，不以拉伸 canvas 填滿容器。
- `ResizeObserver` 監看遊戲 canvas 容器；尺寸變更時更新 renderer size、相機 frustum 及 pointer picking 映射。
- `WebGLRenderer` 設 `outputColorSpace = THREE.SRGBColorSpace`、抗鋸齒與 `powerPreference: "high-performance"`。
- 像素比上限為桌面 2、手機 1.5；避免高 DPI 裝置以過大的 backing buffer 渲染。

### 13.3 InstancedMesh 與更新

- 以 `InstancedMesh` 批次繪製同種面板及符號；逐事件改變受影響索引的矩陣。
- 每次更新一批 instance 後只設定一次 `instanceMatrix.needsUpdate = true`。
- 空格不配置面板 instance；設定 instance count 時依種類連續排列索引。
- 消除／升盤／落下提供 tile ID transitions，renderer 以 ID 維持動畫物件對應；核心仍以棋盤格作規則座標。
- 固定重用 Matrix4、Vector3、Quaternion、顏色和粒子陣列；`render()` 迴圈不得為 72 格建立新物件。
- 粒子採固定容量 pool，滿載時覆用最舊粒子；減少動態效果或手機低效能模式降低數量與特效尺寸。

### 13.4 動畫協定

Renderer 消費核心事件，依設定的 duration 播放 transform：

| 事件 | 表現 |
| --- | --- |
| `PANELS_SWAPPED` | 兩片沿水平軸滑動至交換位置。 |
| `CLEAR_STARTED` | 命中面板短暫放大、發光並淡出；同時產生少量綻放粒子。 |
| `GRAVITY_STARTED` | 以 tile ID 從來源格插值到目的格，落地時短促縮放回彈。 |
| `BOARD_RAISED` | 全部現有面板上移一格，新列由下緣滑入。 |
| `RISE_WARNING` | 頂框警示色脈動並更新 DOM 警示文字。 |
| `CHAIN_UPDATED` | DOM 顯示連鎖文字；背景播放短促、逐層提高音高的提示。 |
| `GAME_OVER` | 盤面頂端花瓣碎裂淡出，結果介面顯示最終分數。 |

Tween 時間只能影響視覺。當動畫被暫停、降階或縮短時，核心狀態與勝負結果不變。`prefers-reduced-motion` 或設定開啟時，停用鏡頭震動、粒子爆發和回彈；保留位置、顏色及文字提示。

## 十四、DOM、可及性與響應式版面

Three.js canvas 只顯示盤面與短暫視覺效果。主選單、模式選擇、分數、時間、暫停、結果與設定一律使用 HTML/CSS；避免把可讀資訊烘焙成 canvas 文字。

- canvas 具備 `tabindex="0"` 與包含操作方式的 `aria-label`。
- 以單一 `aria-live="polite"` 區域宣告分數變化、連鎖、警示、暫停和結果；限制更新頻率，避免每影格播報。
- 上升危險用文字、圖示與邊框變化共同提示，不只靠紅色或閃爍。
- 五種花瓣除了顏色也有不同外形／符號，降低色覺辨識負擔。
- DOM 焦點離開 canvas 時不攔截一般表單或按鈕鍵盤操作。
- 320 CSS px 寬度下完整呈現盤面；以 CSS Grid/Flex 排布 HUD，canvas 容器不扭曲格子比例。

## 十五、音效系統

`audio.mjs` 管理單一 `AudioContext`、master gain、效果音與解鎖狀態。第一次使用者點擊／按鍵後建立或 resume AudioContext。

建議介面：

```js
{
  unlock(),
  play(name, { volume, pitch }),
  setVolume(value),
  setMuted(value),
  suspend(),
  resume(),
  destroy()
}
```

- 交換、消除、落下、升盤、警示與連鎖使用短音效或程序化音色。
- 音量限制於 `0～1`；連鎖音高須設上限。
- 暫停、背景分頁和結果狀態 suspend 音訊；返回遊戲需恢復 AudioContext。
- 音訊資源不存在或初始化遭拒時靜音繼續，不顯示致命錯誤。

## 十六、存檔整合

不保存進行中的盤面。profile 格式與遊戲規格一致：

```js
{
  version: 1,
  bestScore: { endless: 0, timeAttack: 0 },
  bestChain: { endless: 0, timeAttack: 0 },
  settings: {
    soundEnabled: true,
    soundVolume: 0.7,
    reducedMotion: false,
    highContrastPanels: false
  }
}
```

使用既有 `PuzzleSave` 介面：

```js
window.PuzzleSave.create({
  key: "bloom-chain",
  autoRestore: true,
  fresh: createDefaultProfile,
  restore: restoreProfile,
  validate: validateProfile,
  hasProgress: hasMeaningfulProgress,
  getState: serializeProfile
});
```

- 共用系統負責本機與雲端同步；有 `PuzzleSave` 時不可另建第二個 localStorage key。
- `save-adapter.mjs` 驗證有限非負分數、合法模式、音量範圍及布林設定；缺欄補預設，未知欄忽略。
- 每局結束及設定變更時呼叫 controller `save(true)`；不要每一影格存檔。
- 如果共用 runtime 未載入，才用直接 `localStorage` 降級 adapter，寫入獨立的 `bloom-chain-save-fallback-v1` key，避免和 `PuzzleSave` 的 checkpoint envelope 衝突。
- `PuzzleSave` 恢復可用時，等待其 `ready` 後檢查啟動期間是否呼叫過 `restore`。只有沒有受管理存檔時才驗證並匯入 fallback profile，接著呼叫 `save(true)`；已有受管理存檔時沿用該存檔並清除舊 fallback，避免舊本機資料覆蓋較新的雲端進度。
- 損壞存檔不得阻止開始遊戲；保留可驗證的設定，無效紀錄回復預設。

## 十七、錯誤處理與生命週期

- WebGL 2／renderer 初始化失敗：停止建立遊戲 loop，顯示 DOM 錯誤面板與返回大廳連結。
- Three.js CDN 載入失敗：顯示「遊戲載入失敗，請檢查網路後重新整理」；不得留在空白棋盤。
- PuzzleSave、localStorage、音訊或粒子初始化失敗：記錄一次錯誤並讓本局可玩。
- `visibilitychange` 進入 hidden 時自動暫停，清除按住中的移動輸入；回到前景後等待玩家繼續。
- 結束頁面或重建 renderer 時取消 RAF、解除 DOM listener、dispose geometry/material/renderer 並清空粒子 pool。
- 未知 phase、無效盤面長度或非法面板值屬不可恢復錯誤：停止遊戲迴圈且不覆寫存檔。

## 十八、效能預算

| 指標 | 目標 |
| --- | --- |
| 每格盤面解析 | 72 格掃描小於 1 ms（桌面及近五年中階手機）。 |
| Renderer draw calls | 一般盤面不超過 25 次。 |
| 粒子 | 桌面最多 160；手機最多 80；低效能模式最多 32。 |
| 每影格記憶體配置 | 不為面板、矩陣或粒子建立無界新物件。 |
| 目標更新率 | 60 FPS；最低可操作 30 FPS。 |
| 最大固定步進補算 | 每 RAF 最多 6 步，單幀輸入時間最多計入 100 ms。 |
| 首屏外部 runtime | 只載入固定版號 Three.js module 與專案既有存檔 scripts。 |

不引入 bloom 後處理、陰影貼圖或大型外部模型作為玩法必要條件。先量測盤面填滿、多人群同時消除、連續升盤和粒子上限情況，再考慮新增效果。

## 十九、核心測試策略

核心測試使用固定盤面與固定 seed，不開瀏覽器、不建立 WebGL context：

- 水平與垂直三連、四連、五連皆正確消除；斜向三格不消除。
- 相交連線重疊格只清除一次；相連與分離群組數正確。
- 無匹配交換不回復；兩個空格不交換；格子邊界不越界。
- settling 期間第二次交換無效；clear 期間不能移動待清或待處理面板；fall 期間 busy source／destination 不可交換。
- clear／fall 中成立的待處理群組以 tile ID 追蹤，落下後仍正確清除並計為連鎖。
- clear／fall 中操作其他位置後，穩定點會把重力新產生的群組併入待處理消除。
- 各欄重力維持相對順序、tile ID 跟隨面板、位移事件正確。
- 由落下和主動交換建立的後續匹配會計入新連鎖層數。
- 同輪交疊消除群不重算；分離群組分數正確。
- 上升計時在解析期間累積；佇列不超過 2；滿列時停止計時，穩定後逐列執行。
- 頂列空與非空時升盤結果不同；限時歸零後停止升盤及輸入。
- 同 seed、同命令、同固定 step 序列產生相同盤面、分數和事件順序。
- profile 預設、驗證、缺欄補值、未知欄忽略及損壞資料恢復。

Canvas、WebGL 與 DOM 的視覺驗收使用手動瀏覽器檢查：鍵盤焦點、窄螢幕直向、觸控交換、背景暫停、WebGL 錯誤面板、色弱符號及降低動態效果。

## 二十、實作順序

### 階段 1：盤面核心

1. 建立 `config.mjs`、`rng.mjs` 與盤面資料模型。
2. 完成安全起始盤面、交換、直線匹配、分群計數、下落與計分。
3. 完成解析相位、動畫期間的交換、主動連鎖與上升佇列。
4. 以固定 seed 補齊核心單元測試。

### 階段 2：Three.js 最小可玩頁面

1. 建立 HTML、CSS、import map、OrthographicCamera 和棋盤格。
2. 用 `InstancedMesh` 顯示五種花瓣和游標。
3. 接上固定步進、鍵盤、滑鼠／觸控與 DOM HUD。
4. 完成無盡生存的消除、下落、升盤及失敗循環。

### 階段 3：完整操作與保留資料

1. 加入限時挑戰、暫停、結果介面與背景自動暫停。
2. 加入粒子、音效、減少動態效果及高對比面板設定。
3. 接上 PuzzleSave、本機 fallback 與設定保存。
4. 手動檢查手機尺寸、WebGL 錯誤處理及鍵盤／觸控操作。

### 階段 4：專案整合

1. 遊戲可玩後再更新根目錄 `index.html` 遊戲卡與 metadata。
2. 有正式縮圖後再加入 Open Graph 圖片引用。
3. 確認 Firebase 存檔清單是否採白名單；若有，依現有資料結構新增 `bloom-chain`。
4. 執行核心測試、`git diff --check` 與 GitHub Pages 路徑 smoke test。

## 二十一、技術完成定義

- Three.js 負責所有盤面格、花瓣面板與盤面特效渲染。
- 核心可在沒有 DOM、Three.js、Web Audio 或瀏覽器的 Node 環境執行。
- 規格書第十一節驗收條件均可由核心案例或瀏覽器手動驗收。
- 同 seed 和同命令序列產生相同棋盤、事件、分數與勝負結果。
- 遊戲暫停、切背景、失焦、音訊失敗或存檔失敗不會破壞當局狀態。
- 6 × 12 盤面、升盤和連鎖在桌面與手機保持可讀、可操作。
- 色彩以外有明確面板符號，且有完整鍵盤操作與結果播報。
- 達到第十八節效能預算，不建立無上限 Mesh、DOM 節點或 timer。
- 從 Puzzle Club GitHub Pages 的相對路徑可載入、返回大廳與正常存檔。
