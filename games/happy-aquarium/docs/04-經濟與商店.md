## 10. 商店、買賣與交易規則

### 10.1 購買流程

所有購買以 `canPurchase → confirmPurchase → commitTransaction` 三階段執行：

1. 驗證持有物前置條件、庫存、金額與商品是否有效；魚隻數量不得作為購買失敗條件。
2. 500 金幣以上或寶石交易顯示確認；其餘單擊購買。
3. 同一同步 tick 內先扣款再建立物品；建立失敗必須回滾扣款。
4. 交易完成後寫入 transaction log、發布 state snapshot 並呼叫 urgent save；DOM 與 Phaser 只訂閱結果，不得自行補扣款或補發物品。
5. 每次 command 由 `input-adapter` 建立 UUID `transactionId`。核心把最近 50 筆成功交易 ID 與摘要保存為 ring buffer；連點、雙擊、觸控重送、Scene restart 或存檔恢復後收到相同 ID 時，回傳原結果但不再次扣款或發獎。
6. 超過 50 筆的舊交易摘要可移除，但同一畫面未完成的 command 不得重用 ID；失敗交易不占成功 ring buffer，UI 可用新 ID 重新嘗試。

淨利/小時為 `(成魚售價 - 卵價) ÷ 成長小時` 後四捨五入到整數，只計卵價與成長時間，不含照護、耗材、設備、魚位占用與離線停滯。它只能比較名目產值；平衡測試還要記錄每魚位的照護後淨利與玩家操作時間，避免後期只剩單一最優魚種。

月光魚持有前置滿足後仍只在 `Asia/Taipei` 18:00～06:00 顯示可購買，其他時間保留商品卡並顯示夜間倒數；已擁有的月光魚不受時段影響。彩虹美人魚永遠不出現在一般購買清單。

### 10.3 階段、狀態與變種修正

```text
baseSell = adultSellPrice × stageMultiplier
stageMultiplier: fry 0.25, juvenile 0.60, adult 1.00
variantMultiplier: normal 1.00, shiny 2.00
conditionMultiplier: healthy 1.00, sick 0.50, dead 0
finalSell = floor(baseSell × variantMultiplier × conditionMultiplier)
```

- 放入魚缸前的未孵化魚卵可退貨，返還卵價 70%；放入後不可出售 egg，只能取消並返還 50%。
- 受訓費用、已消耗飼料與藥物不計入售價。
- 售價 1,000 以上、亮鱗魚、已命名魚或唯一一隻該物種必須二次確認。
- 賣魚後魚立即從模擬移除並發放金幣。
- 商店價格首版固定，不隨時間與玩家庫存變動。
