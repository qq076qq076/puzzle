# 快樂水族箱：遊戲核心與進度

> 用途：遊戲定位、初始資源、等級、魚缸容量與時間規則。
> [返回規格索引](../遊戲規格書.md)

## 1. 文件目的

本規格定義首個可公開遊玩的完整版本，供企劃、工程、美術與測試共同使用。凡是影響玩家資源、動物狀態、時間推進、存檔內容或操作結果的規則，都必須在本文件或集中設定檔中有唯一來源，不得散落在 UI 常數與動畫程式內。

### 1.1 設計目標

- 玩家在 3 分鐘內完成買卵、孵化、餵食與第一次成長回饋。為達成此目標，僅新存檔第一顆教學孔雀魚卵套用 `tutorialHatchOverrideMs = 60_000`；孵化後 fry、juvenile 仍依正常設定推進，往後所有魚卵不再加速。第一次餵食後 1 秒內顯示成長條開始推進與一次脈衝提示，「第一次成長回饋」不代表直接升到 juvenile。
- 短期操作以餵食、清潔、收取事件為主；中長期決策以買賣、繁殖、設備與收藏為主。
- 離線會推進世界，但不以死亡懲罰一般玩家；長期不照顧仍會付出效率與維護成本。
- 便宜魚提供快速周轉，高級魚提供較高的單次絕對利潤與收藏價值。
- 99 隻魚的極端存檔仍能操作，正常目標為 15～40 隻。
- 不設付費點、不售賣寶石、不包含廣告。

### 1.2 完整版範圍

- 1 座可命名主魚缸。
- 14 種正式魚類、3 種清潔生物、6 種設備。
- 魚卵、成長、飽食、生病、死亡、復活、買賣與繁殖。
- 手動餵食、擦藻、藥水、藻錠、濾芯與設備排程。
- 30 筆裝飾外觀（29 種獨立裝飾＋暖燈設備的靜態外觀）、訪客、寶箱、漂流瓶、每日任務與成就。
- 本機存檔、Firebase 雲端存檔與離線結算報告。

### 1.3 不在首版範圍

- 多魚缸、玩家交易、競標、市場浮動價格。
- 即時多人、好友拜訪、排行榜、公會。
- 付費商店、廣告、推播通知。
- 魚類基因配色編輯、裝飾碰撞建模、伺服器權威防作弊。

## 2. 核心循環與成功條件

```text
購買魚卵 → 孵化與餵食 → 成長為成魚 → 出售或保留繁殖
     ↑                                      ↓
補充耗材 ← 購買設備／裝飾 ← 金幣、EXP、碎片、寶石
     ↑                                      ↓
清潔與治療 ← 訪客、表演、寶箱與每日任務 ← 提升魚缸吸引力
```

本作沒有傳統通關畫面。Lv50、收集全部 14 種魚、養出彩虹美人魚及完成全部成就視為長期完成目標；玩家仍可繼續經營。

## 3. 初始狀態與玩家資源

### 3.1 新存檔

| 欄位 | 初始值 |
| --- | ---: |
| 玩家等級 | 1 |
| 當級 EXP | 0 |
| 金幣 | 300 |
| 寶石 | 3 |
| 養魚上限 | 15 |
| 清潔度 | 100 |
| 魚與設備 | 無 |
| 藻錠 | 2 |
| 藥水 | 1 |
| 裝飾 | 無 |

新手任務固定為下列四步；每個 reward ID 只能領取一次。第一顆卵孵化後生成 1 個教學藻斑，即使清潔度為 100 也可擦除。

| Reward ID／步驟 | 獎勵 |
| --- | --- |
| `buy-first-egg` 購買孔雀魚卵 | 30 金幣、10 EXP |
| `hatch-first-egg` 孵化 | 50 金幣、15 EXP |
| `feed-first-fish` 餵到第一顆魚糧 | 50 金幣、15 EXP |
| `clean-first-algae` 擦除教學藻斑 | 50 金幣、20 EXP、水榕 1 盆 |

四步合計 180 金幣、60 EXP 與一盆水榕；一般動作本身的 EXP 另外照 §15.1 發放。首次成魚與出售另列後續里程碑，不阻塞新手引導完成。

| 類型 | 用途 | 取得方式 | 上限 |
| --- | --- | --- | ---: |
| 金幣 | 買卵、用品、設備、裝飾、訓練 | 賣魚、訪客、任務、寶箱 | `9,999,999,999` |
| EXP | 升級與解鎖 | 照護、成長、買賣、繁殖、任務 | Lv50 後停止累積 |

所有加減資源必須通過單一交易函式；UI 不得直接改寫錢包欄位。金額均為整數，任何計算結果最後使用 `Math.floor`。

## 4. 玩家等級與解鎖

升級需求指「目前等級升到下一級所需的當級 EXP」：

```text
requiredExp(level) = round(100 × level × (1 + level / 10))
```

一次獲得大量 EXP 可以連升多級。升級後當級 EXP 扣除需求值並保留溢出；Lv50 時固定顯示 `MAX`。

| 等級 | 主要解鎖 |
| ---: | --- |
| 1 | 小蝦虎、孔雀魚、基礎照護、一般裝飾 |
| 3 | 燈籠魚、強化清潔刷 |
| 5 | 黃金錦鯉、蘋果螺 |
| 6 | 斑馬魚 |
| 8 | 繁殖、氣泡石、第一次擴缸任務 |
| 10 | 小丑魚、藍魔鬼 |
| 12 | 訓練表演、基礎自動餵食器 |
| 16 | 神仙魚、獅子魚、清潔蝦、暖燈 |
| 20 | 月光魚、清道夫魚、外掛過濾器 |
| 25 | 龍魚、電鰻、進階餵食器 |
| 32 | 魟魚、UV 殺菌燈 |
| 40 | 彩虹美人魚繁殖條件、珊瑚門 |
| 50 | 等級上限紀念裝飾與成就 |

每次升級獲得 `100 + 25 × 新等級` 金幣。Lv10、20、30、40、50 另給 1 顆寶石。

## 5. 魚缸世界與座標

### 5.1 邏輯座標

- Phaser world 固定為 `1000 × 600` 邏輯像素，由 Scale Manager 的 `FIT` 模式等比例縮放。
- 可游動水域：`x = 40～960`、`y = 75～550`。
- 水面互動帶：`y = 55～105`；底砂帶：`y = 510～570`。
- 位置存檔使用 `x / 1000`、`y / 600` 的 0～1 正規化數值，避免不同螢幕恢復時位移。
- 裝飾位置同樣正規化；裝飾的邏輯碰撞只用於避免魚中心穿過大型物件，不做精確像素碰撞。

### 5.2 畫面縮放

- Phaser renderer 維持 `1000×600` 的內部繪製尺寸，Scale Manager 只調整顯示大小；UI 程式不手動改 canvas backing store。若日後要加入高 DPI render target，需先以中階手機 GPU 記憶體與 frame time 驗證，不能只依 `devicePixelRatio` 無上限放大。
- 桌面魚缸比例固定 5:3。手機直向使用等比例縮放並保留 letterbox；DOM 工具列與 bottom sheet 重排，不裁切或壓扁遊戲世界。
- 指標轉世界座標統一使用 Phaser camera 的 `getWorldPoint()`；DOM 需要對準世界物件時，則由單一 projection helper 依 camera transform 與 canvas bounding rect 換算。業務邏輯不得自行計算 canvas 比例。
- 容器尺寸變化由 Phaser Scale Manager 處理；`ResizeObserver` 僅可用於重排外部 DOM，不可重設 Phaser canvas。

### 5.3 養魚與裝飾上限

- 魚卵一放入魚缸就占用 1 個養魚名額。
- 等級容量為 `15 + floor((level - 1) / 2)`，即 Lv3、5、7……49 各 +1。
- Lv8、16、24、32 各有一個具永久 ID 的擴缸任務，完成後 +5；可花 3 寶石提前完成。任務完成旗標只寫入一次，提前完成後到達原等級不得再次加容量。
- Lv50 且完成四個擴缸任務時容量為 59；99 是存檔與效能的硬上限，保留給未來擴充。任何購買、繁殖或寶箱獲卵都不得突破目前容量或硬上限。
- 裝飾同時擺放上限 10；倉庫沒有件數上限。
- 清潔生物與設備不占魚數，每種清潔生物最多 1 隻。設備按功能槽安裝：餵食、過濾、成長燈、殺菌、打氣各 1 槽；基礎與進階餵食器互斥，替換時舊設備回到倉庫，不自動出售或遺失排程資料。

## 6. 即時模擬與時間系統

### 6.1 遊戲迴圈

```text
Phaser Game Loop
  → AquariumScene.update(time, delta)
  → delta clamp 至 100 ms 並累積
  → 以 1/60 秒 fixed step 更新 animal-ai，單幀最多追趕 5 step
  → 將核心 snapshot 同步到 Sprite／Animation／depth
  → DOM 狀態以最多 10 Hz、事件驅動方式更新
```

- 移動、食物與動畫使用單調時間 `performance.now()`。
- 成長、飽食、設備、繁殖與事件使用 Unix 毫秒 `Date.now()`。
- 所有「每日／自然日／夜間」規則統一使用 `Asia/Taipei`：`dayKey`、任務重置、表演次數、疾病日判定、月光魚商店與設備每日排程不得混用裝置當地時區。存檔保存 epoch 毫秒或該時區的一日分鐘數，不保存格式化日期字串作運算。
- 分頁隱藏時透過 Phaser lifecycle 暫停 Scene 的逐幀模擬並立即存檔；回來後先走離線結算，再恢復 Scene，不追趕數萬個移動 frame。
- 系統時間倒退超過 5 分鐘時，該段 elapsed 視為 0 並顯示一次非阻塞提示。
- 單次線上更新若 elapsed 超過 60 秒，改交由離線結算器處理。

### 6.2 離線結算上限

- 生物與設備狀態最多結算 7 天；超過部分不再產生額外收益。
- 訪客小費最多結算 24 小時或 12 批訪客，以較小者為準。
- 寶箱／漂流瓶最多累積 3 個。
- 若魚隻離線前 `satiety >= 25`，離線後最低停在 25；若離線前已低於 25，飢餓與生病倒數正常推進。此保護不套用清潔生物，清潔生物可降到 0 並停工但不消失。
- 清潔度離線最低停在 10。
- 結算以事件時間點排序，必須可重複執行而不重複發獎；完成後立即更新 `lastProcessedAt`。
