# 快樂水族箱：技術架構與資料

> 用途：程式架構、資料模型、存檔同步與離線結算演算法。
> [返回規格索引](../遊戲規格書.md)

## 18. 技術架構

### 18.1 技術選擇

- 鎖定 **Phaser 4.2.1**、Vite、原生 JavaScript ES modules 與 HTML/CSS，不引入 React、Vue 等 UI 框架。
- 魚缸使用 Phaser WebGL renderer；不使用已被 Phaser 4 官方標記為 deprecated 的 Phaser Canvas renderer。[Phaser 4 releases](https://phaser.io/download/phaser4)、[Phaser 4 renderer](https://phaser.io/news/2026/04/phaser-4-renderer-faster-cleaner-and-built-for-modern-games)
- 商店、倉庫、任務、設定、狀態卡、確認視窗與離線報告使用 DOM；Phaser 不重做捲動列表、輸入框、焦點管理與響應式排版。
- 遊戲核心、經濟、生命週期、RNG、離線結算與存檔 schema 使用不依賴 Phaser／DOM 的純 JavaScript，Node.js 可直接執行單元測試。
- 不啟用 Arcade Physics 或 Matter.js。魚群使用既有 steering 與 spatial hash；Phaser Sprite 只呈現核心計算出的 transform。
- Firebase 只透過現有 `games/firebase-runtime.js` 與 `games/save-system.js` 連接；Phaser Scene 不直接存取 Firebase。
- `package.json` 對 `phaser` 使用精確版本 `4.2.1`，提交 lockfile；Vite 版本由 lockfile 固定，不使用執行時 CDN。

#### 18.1.1 架構邊界與決策理由

| 工作 | 採用 | 理由 |
| --- | --- | --- |
| 魚、食物、裝飾擺放、世界指標、動畫、特效、音效 | Phaser | 同一座標系、Display List、Animation、Loader、Input 與 GPU batching 已完整提供 |
| HUD、商店、倉庫、任務、設定、狀態卡、dialog、bottom sheet | DOM/CSS | 原生支援捲動、文字換行、表單、鍵盤焦點、螢幕閱讀器與響應式布局 |
| 經濟、生命週期、交易、離線結算、RNG、存檔 | 純 JavaScript core | 可在 Node 測試、避免 Scene 重啟改變資料、使渲染技術可替換 |

不採「全部 Phaser」是因為大量管理介面會被迫自行重做 layout、scroll、focus trap、文字選取與可及性，還會讓交易資料容易綁死 Scene 生命週期。不採「全部原生 Canvas」則是避免重做素材 Loader、動畫、輸入命中、Scene 與 WebGL 渲染。只有跟世界座標緊密耦合、短暫且非主要資訊的提示留在 Phaser；可操作或需閱讀的資訊必須有 DOM 對應。

首版不加 React／Vue，是因為 DOM UI 由單一 controller 與少量面板即可管理；若日後出現跨頁路由、數十個相依表單或難以維護的手動 DOM diff，再以量測到的複雜度另立決策，不預先增加第二套狀態框架。

### 18.2 分層與資料流

```text
DOM UI ──command──> game-core ──domain events──> DOM UI
                       │
                       ├──render snapshot──> Phaser AquariumScene
                       │
                       └──serializable state──> save-adapter ──> PuzzleSave

Phaser pointer ──intent──> input-adapter ──command──> game-core
```

- `game-core` 是金幣、物品、魚隻生命週期與交易結果的唯一真相來源。
- `AquariumScene` 可以保存短生命週期的 Sprite、Tween、粒子與目前速度，但不得直接改金幣、飽食、成長、背包或任務。
- Phaser Registry 只放唯讀服務參照或畫面偏好，不作為正式遊戲存檔。
- DOM 與 Phaser 都只能送出 intent／command；成功後依同一份 state snapshot 更新，避免雙重狀態。
- Scene 被 restart、sleep 或 destroy 時不得造成重複發獎、重複交易或離線時間重算。

### 18.4 Phaser 設定與 Scene

```js
const phaserConfig = {
  type: Phaser.WEBGL,
  parent: "aquarium-stage",
  width: 1000,
  height: 600,
  backgroundColor: "#0b6f91",
  render: {
    antialias: true,
    smoothPixelArt: true,
    roundPixels: false
  },
  scale: {
    mode: Phaser.Scale.FIT,
    autoCenter: Phaser.Scale.CENTER_BOTH
  },
  scene: [BootScene, AquariumScene, EffectsScene]
};
```

- 使用 `WEBGL` 而非 `AUTO`，啟動失敗時顯示 DOM 錯誤面板，不靜默退回 deprecated Canvas renderer。
- `FIT` 保持 `1000×600` 邏輯世界與比例；DOM UI 依容器尺寸排版，不跟著 Phaser camera 縮放。[Phaser Scale Manager](https://docs.phaser.io/phaser/concepts/scale-manager)
- `BootScene` 載入 manifest、catalog、首屏 UI、互動物件與新手魚素材，建立全域動畫後啟動主場景。[Phaser Animations](https://docs.phaser.io/phaser/concepts/animations)
- `AquariumScene` 管理魚、幫手、裝飾、食物、深度排序與 world pointer。
- 設備位置來自 `DEVICE_PLACEMENTS`，不以購買索引排列：餅食器在右上水面、外掛過濾器與 UV 燈靠缸壁、暖燈靠上緣、氣泡石在砂地。
- `?dev=true` 由 `main.js` 在建立核心前偵測；開發模式不匯入 Firebase／PuzzleSave、不取得 writer lock，也不建立 localStorage checkpoint。
- `EffectsScene` 透明疊在 AquariumScene 上，只管理氣泡、浮字、愛心、閃光與降低特效模式；可獨立 sleep。
- 全遊戲只有一個 `Phaser.Game` 實例。Scene 的 input、tween、timer 與 listener 必須在 shutdown 時解除。[Phaser Scenes](https://docs.phaser.io/phaser/concepts/scenes)

### 18.5 模組責任

- `game-core`：接收 command，驗證後回傳新狀態與 domain events。
- `simulation`：根據時間戳推進數值，不負責逐幀位置。
- `animal-ai`：以固定 step 處理可見期間的位置與行為，不直接加錢或改背包，也不依賴 Phaser 類別。
- `AquariumScene`／`fish-view`：將 snapshot 同步到 Phaser Sprite、Animation、depth、flipX 與 hit area。
- `ui-controller`：把事件轉成畫面與音效，不直接改 state。
- `save-adapter`：schema migration、驗證、還原與輸出。
- `input-adapter`：把 Phaser pointer 與 DOM action 正規化為 command；不得從按鈕 dataset 接受價格。[Phaser Input](https://docs.phaser.io/phaser/concepts/input)

### 18.6 Command 與事件

主要 command：

```text
BUY_ITEM, BUY_CONSUMABLE, SELECT_FOOD, PLACE_EGG, FEED, CLEAN_ALGAE, USE_MEDICINE,
SELL_FISH, START_BREEDING, TRAIN_FISH, PERFORM,
INSTALL_DEVICE, REFILL_DEVICE, PLACE_DECORATION,
CLAIM_VISITOR_TIP, OPEN_REWARD, CLAIM_QUEST
```

每個 command 回傳 `{ transactionId, ok, state, events, errorCode }`。失敗 command 不得產生部分狀態；成功的 `transactionId` 與結果摘要寫入最近 50 筆 ring buffer，相同 ID 重送時直接回傳既有結果。常用事件包含 `currencyChanged`、`fishAdded`、`fishSold`、`foodDropped`、`foodEaten`、`rewardGranted`、`saveUrgent`。

### 18.7 素材打包與載入

- `asset-registry.js` 使用 Vite `import.meta.glob("../../assets/runtime/**/*.png", { eager: true, query: "?url", import: "default" })` 建立「正式相對路徑 → build 後 URL」表，確保動態物種路徑仍會被打包。[Vite glob import](https://vite.dev/guide/features.html#glob-import)
- `manifest.json` 與 `catalog.json` 由 ES module 直接匯入；遊戲邏輯不得掃描資料夾猜測素材。
- 魚類固定格位圖以 `this.load.spritesheet(key, url, { frameWidth: 64, frameHeight: 64 })` 載入；Phaser 對固定格位檔案使用 spritesheet，而不是需要額外 JSON 的 texture atlas。[Phaser Loader](https://docs.phaser.io/phaser/concepts/loader)
- BootScene 先載入共同素材；未解鎖魚種可以延後到商店首次需要預覽時載入。載入完成前商品卡顯示 skeleton，不建立缺 texture 的 Sprite。
- texture key 使用 `fish:<species-id>`、`helper:<id>:<state>`、`device:<id>:<state>` 等命名空間，禁止只使用容易衝突的裸 ID。
- 生產建置必須輸出自包含的 `dist/`，Pages workflow 執行 `pnpm install --frozen-lockfile → pnpm test → pnpm build`，再用 build 結果取代站台內的 `games/happy-aquarium/`。

### 18.8 集中設定

下列數值只能存在 `src/config/game-config.js`：價格、售價、時間、持有物前置、移速、掉落權重、清潔公式係數與動畫行為參數。Phaser Scene 不得另外保存一份數值。規格表與設定不一致時，先修改規格並說明平衡理由。

### 18.9 開發、建置與共用腳本

`package.json` 至少提供下列指令；CI 使用 Node.js 22，`phaser` 固定精確版本，Vite 由 lockfile 固定：

```json
{
  "type": "module",
  "scripts": {
    "dev": "vite",
    "test": "node --test",
    "build": "vite build",
    "preview": "vite preview",
    "check": "pnpm test && pnpm build"
  },
  "dependencies": { "phaser": "4.2.1" },
  "devDependencies": { "vite": "^7.0.0" }
}
```

`vite.config.js` 使用相對 base，並關閉 public directory，避免把 `assets/source/`、製作文檔與工具誤複製到 production。只被 `asset-registry.js` 引用的 runtime 檔案會進入 build：[Vite static assets](https://vite.dev/guide/assets.html)

```js
import { fileURLToPath, URL } from "node:url";
import { defineConfig } from "vite";

export default defineConfig({
  base: "./",
  publicDir: false,
  server: {
    fs: { allow: [fileURLToPath(new URL("..", import.meta.url))] }
  },
  build: {
    target: "es2022",
    assetsInlineLimit: 0,
    sourcemap: true,
    rollupOptions: { output: { manualChunks: { phaser: ["phaser"] } } }
  }
});
```

`shared-runtime.js` 依序以 side-effect import 載入 `../../../firebase-config.js`、`../../../firebase-runtime.js`、`../../../save-system.js`，由 Vite 一併打包。`index.html` 只載入 module entry，不依賴部署位置的 `../` script URL；共用腳本更新後必須重建本遊戲。

### 19.1 開發模式

- URL 參數只有在 `dev=true` 時啟用；其他值不生效。
- 所有持有物前置、夜間販售與裝飾同時擺放上限都不阻擋測試操作；金幣價格不扣款，UI 顯示 `∞`。

## 20. 存檔、同步與資料驗證

### 20.1 PuzzleSave 接入

`main.js` 最先匯入 `integration/shared-runtime.js`，再建立純核心與 DOM shell並呼叫 `PuzzleSave.create()`。遊戲使用 `autoRestore: true`：啟動時自動比較 Firebase 雲端與本機 checkpoint，還原最新的有效進度，不顯示「繼續／重新開始」選擇對話框。`fresh()`／`restore()` 必須在 Phaser 建立前完成，`main.js` 等待 controller 的 `ready` Promise 後才建立場景，避免新遊戲畫面短暫覆蓋雲端進度。

```js
window.PuzzleSave.create({
  key: "happy-aquarium",
  fresh,
  restore,
  validate,
  getState,
  hasProgress,
  autoRestore: true,
  interval: 2000,
  cloudInterval: 5000
});
```

- 本機 key 為 `puzzle-club-save:happy-aquarium:v1`。
- Firebase 可用時先等待匿名／帳號驗證與雲端讀取；雲端不可用時自動降級讀取本機 checkpoint，不阻斷遊戲。
- 雲端與本機都有存檔時，使用存檔時間選擇較新者；選定後立即開始 2 秒自動存檔與 5 秒雲端佇列。
- 買賣、寶石、每日目標完成、里程碑魚、獎勵開啟、重設遊戲使用 urgent save。
- 一般移動位置不要求每 frame 存檔；2 秒 snapshot 保存最後正規化位置。
- 最近 50 筆成功交易 ID 與摘要必須一起存檔，使頁面重載、Scene restart 或雲端恢復後的重送仍具冪等性；摘要不得保存完整 state 或敏感資料。
- `fresh()`、`restore()` 與 `getState()` 不得共享可被外部改寫的物件引用。

### 20.2 Firebase 必要修改

`happy-aquarium` 已加入 `games/firebase-runtime.js` 的 `SAVE_KEYS` 與 Firestore 規則白名單。Firestore 路徑沿用 `users/{uid}/saves/happy-aquarium`，不直接從遊戲呼叫 Firestore SDK；UI 僅在 Firebase status 為 `online` 時顯示雲端已同步，連線或權限失敗時改顯示本機存檔。

### 20.3 驗證與 migration

- `schemaVersion` 未知或必要根節點不存在時拒絕還原並保留原始字串供除錯，不得部分載入。
- 數值驗證必須檢查 finite，再 clamp 合法範圍；`NaN`、`Infinity` 不可進入 state。
- species、device、decoration ID 必須存在設定檔；未知 ID 移到 `recovery.unknownItems`，不渲染也不刪除。
- 重複永久 ID 只保留第一筆，其餘重新產生 ID 並記錄 migration warning。
- 金幣、寶石不得為負；魚數超過 99 時，多餘魚移入 recovery inventory，不直接消失。
- 教學步驟、一次性獎勵 ID 與 `firstEggOverrideConsumed` 必須驗證並保存；舊版缺欄位時依「是否已有魚／卵或買卵統計」推導為已消耗，不能因 migration 再送一次加速或獎勵。
- `transactions.recentIds` 與 `transactions.recent` 各最多 50 筆；去除格式錯誤、重複或不存在摘要的 ID，舊版缺少此欄位時 migration 建立空 ring buffer。
- migration 必須是純函式 `vN → vN+1`，每個版本有 fixture 測試。

### 20.4 單一 writer 與衝突處理

現有 `save-system.js` 會在每個已開始的分頁建立 autosave，不能把「只有作用中分頁寫入」當成既有能力。養魚遊戲在建立 `PuzzleSave` 前必須先取得同來源單一 writer：

- 優先以 `navigator.locks.request("happy-aquarium-writer", { mode: "exclusive", ifAvailable: true })` 取得 Web Lock，並在遊戲生命週期內持有；所有使用均先 feature-detect。
- 不支援 Web Locks 時才使用 localStorage lease。key 為 `puzzle-club-save:happy-aquarium:writer-lease`，內容為 `{ writerId, expiresAt }`；候選者寫入後等待 50～150 ms 隨機退避並重讀，確認仍為自己的 ID 才啟動遊戲。
- fallback leader 每 3 秒續租，租期 10 秒；`pagehide` 主動釋放。比較時使用 `expiresAt`，但任何單次租期最多接受目前時間後 30 秒，避免時鐘異常造成永久鎖定。
- 未取得 lease 的分頁不呼叫 `PuzzleSave.create()`、不啟動 Phaser input，顯示「遊戲已在另一個分頁開啟」DOM 面板；可在 lease 過期後重新嘗試，不提供強制雙寫。
- 使用 `BroadcastChannel("happy-aquarium-writer")` 即時通知 leader 變化；不支援時以 `storage` event 與定時重查降級。lease 的正確性仍以 localStorage 內容為準，BroadcastChannel 只降低等待時間。

Firebase 的 `serverRevision` 可以拒絕過期寫入，但目前共用層不會把 `accepted: false` 暴露給遊戲。上線前須以向後相容方式替 `PuzzleSave.create()` 增加 `onConflict(remoteCheckpoint)` callback：觸發後停止該 writer 的 autosave／urgent save、保留本地 recovery copy、顯示「其他裝置已有較新進度」，讓玩家載入雲端最新版。魚、金幣、RNG 與交易紀錄不可欄位級自動合併。

## 21. 離線結算演算法

離線期間不模擬游泳路徑，而是處理會改變資料的時間事件：

1. 計算 `from = lastProcessedAt`、`to = min(now, from + 7 days)`。
2. 建立下一個事件：餵食器、濾芯到期、暖燈／UV 排程切換、幸福獎勵、訪客、寶箱、每日重置、生病與死亡。
3. 將連續量（飽食、成長、清潔）積分到最早事件時間。
4. 執行該事件並排入它的下一次時間。
5. 重複到 `to`；單次最多 10,000 個事件，超過時合併相同週期事件。
6. 套用離線友善下限與收益上限，產生摘要，再設定 `lastProcessedAt = now`。

同一份存檔在相同 `from/to/config/RNG` 下必須得到相同結果。重新開啟離線報告只能閱讀上次摘要，不能再次發放。
