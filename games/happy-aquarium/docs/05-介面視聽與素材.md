# 快樂水族箱：介面、視聽與素材

> 用途：桌面與手機操作、可及性、動畫、素材載入與音效。
> [返回規格索引](../遊戲規格書.md)

## 16. 介面與操作

### 16.1 桌面布局

- 頂部只保留金幣與寶石；魚缸上方不放 `tank-status` 區塊，不顯示清潔度、魚隻總數或存檔狀態。
- 中央：Phaser WebGL 魚缸；右側為獨立 DOM 的可收合狀態／事件面板。
- 底部：清潔、藥水、藻錠、漂流禮物、商店、倉庫、任務、設定；不設撒魚糧按鈕。
- 商店分頁：魚卵、照護、清潔生物、設備、裝飾。
- 魚卵商品卡只顯示魚名與購買按鈕，不顯示成長時間或成魚價格說明。

### 16.2 指標與觸控

| 操作 | 結果 |
| --- | --- |
| 點擊空白水域 | 立即在該位置放入 1 顆會緩慢下沉的魚糧，無工具切換與冷卻 |
| 點擊魚缸 | 先檢查點擊位置是否命中旋轉金幣；有金幣就優先撿取且不撒魚糧，沒有金幣與其他控制物件時才放下魚糧 |
| 點擊魚 | 不開啟彈窗，該次點擊視為一般魚缸點擊並放下魚糧 |
| 點擊生物／設備／裝飾 | 開啟對應控制卡；設備與裝飾可調整顯示大小 |
| 拖曳缸壁 | 清除藻斑 |
| 拖曳裝飾 | 編輯模式中移動位置 |
| 長按 500 ms | 開啟物件快捷選單；不得直接出售 |
| Esc／面板外點擊 | 關閉最上層面板 |

- 觸控拖曳超過 12 px 才視為拖曳，避免移動裝飾時誤餵。
- 所有 DOM 按鈕最小 44×44 CSS px。
- 手機狀態卡與商店使用 DOM bottom sheet；開啟時 Phaser 仍可繪圖，但由 `input-adapter` 暫停魚缸指標 intent。
- 交易確認按鈕防連點 500 ms。

### 16.3 回饋與可及性

- 金幣與清潔度變動顯示浮字，但同類浮字每 200 ms 合併。
- 錯誤使用 toast，不使用阻塞式 `alert`；危險交易使用可鍵盤操作的 dialog。
- Phaser canvas 容器有可讀的 `aria-label` 與操作說明；魚的名稱、狀態與可操作項目同步到 DOM 狀態卡，不能只靠畫布像素傳達。
- 商店、倉庫、任務、設定、確認視窗與離線報告一律使用語意化 DOM，具備可見焦點、正確 tab 順序、Esc 關閉與開關面板後的焦點還原。
- 提供音樂、音效、降低動態效果、關閉閃光與高對比模式。
- `prefers-reduced-motion` 下停用鏡頭震動、彩虹尾跡與大量氣泡，但保留狀態辨識。

## 17. 視覺、動畫與音效

### 17.1 素材載入

- 正式路徑只允許 `../assets/runtime/`；`../assets/source/` 不可被打包或由遊戲載入。
- Vite 以 `import.meta.glob` 建立 runtime URL registry；資產 ID、尺寸、動畫列與 FPS 由 `manifest.json`／`catalog.json` 解析，禁止由檔名列舉順序推測用途。
- `BootScene` 透過 Phaser Loader 預載 UI、卵、食物、小蝦虎與孔雀魚；其他魚種在商店首次需要時以第二批 Loader queue 載入，完成前顯示 DOM loading 狀態。
- 固定 `64×64` 格位魚圖使用 `load.spritesheet`，各狀態動畫在全域 Animation Manager 只建立一次；Scene restart 前先用 animation key 檢查，避免重複註冊。
- 圖片載入失敗時使用內建 `__MISSING` texture 搭配物種色碼與 DOM 警告，並以 asset ID 去重記錄 warning；單一非關鍵素材不得令遊戲初始化失敗。
- 像素素材使用 Phaser texture filtering 與 `smoothPixelArt` 的單一全域策略；不要每個 frame 切換平滑設定。縮放與 Texture Manager 行為以技術分冊為準。
- 商店縮圖必須依素材格式分開處理：魚類 `256×384` atlas、幫手／設備 `256×64` strip、裝飾至少 `192×64` 三幀 strip，不得共用錯誤的 background-size。縮圖容器需完整容納一個 `64×64` frame，使用 contain 或正確 frame window，不得以 overflow 或圓角裁掉透明邊界。
- 所有 runtime PNG 必須通過素材稽核：格位尺寸正確、四邊無非預期的不透明像素、無棋盤格伪透明底、無相鄰格位污染，且主體留在每個 `64×64` frame 內。可無損修正的污染直接清除 alpha；必須重畫主體時才使用 ImageGen 保留原造型與色盤進行透明背景修圖。
- 14 種魚各自提供 `<species-id>-turn.png`：`256×64`、4 幀水平 strip，透明背景，表現側面逐步轉成反方向的回頭動作。
- 29 種裝飾與暖燈外觀都要有至少 3 幀；水草／珊瑚使用擺動，燈光／水晶使用明暗呼吸，硬景物使用水光或氣泡變化。Phaser 以每秒 4 幀循環播放。
- 水族箱背景使用獨立 `1000×600` 圖片，包含水色層次、水面光束、遠景與底砂，但不得烘焙魚、設備或可購買裝飾；互動物件仍由 Phaser 分層顯示。

互動動畫 ID 與用途固定如下：`fish-egg-hatch` 孵化、`fish-food-fall` 魚糧、`coin-spin` 可撿取金幣、`algae-wafer-fall` 藻錠、`medicine-use` 治療、`treasure-chest-open` 寶箱、`drift-bottle-bob` 漂流瓶。`fish-food-fall` 固定為 `256×64`、4 幀水平 strip；每幀恰好一顆相同飼料，中心、輪廓大小與留白一致，只改變旋轉角度，禁止用顆數變化表現動畫。

UI 圖示直接使用 catalog ID：`coin`、`gem`、`fish-food`、`algae-wafer`、`medicine`、`cleaning-brush`、`filter-cartridge`、`fertilizer-shard`、`decoration-shard`、`fish-egg`、`visitor-ticket`、`heart`、`clock`、`inventory-crate`、`quest-scroll`。`exp-star` 僅保留為未載入的舊素材，不得重新接回 UI。程式不得以檔案列舉順序推測用途。

### 17.2 繪製順序

```text
背景漸層 → 遠景光帶 → 後景裝飾 → 氣泡／設備
→ 魚與清潔生物 → 前景裝飾 → 食物／互動物件
→ 水面與玻璃效果 → Phaser 世界內狀態提示
```

使用固定 depth band，並只在魚跨越排序門檻時更新 `setDepth()`，不要每幀重排整個 Display List。魚的 depth 由 y 座標映射；死亡浮魚固定在水面層。DOM 面板永遠在 canvas 外層，不參與 Phaser depth。狀態泡泡不得被前景裝飾完全遮住。

裝飾購買後進入待放置狀態，下一次點擊魚缸合法區域決定位置；已放置裝飾可直接拖曳，超過 12 px 才視為拖曳，放開時將正規化座標透過核心命令保存。裝飾中心限制在 `x=0.06～0.94`、`y=0.20～0.90`，不得落到魚缸外或工具列。裝飾預設縮放為 1.45、設備以既有功能位置為基礎放大 1.25 倍；玩家可在控制卡用滑桿自訂裝飾 `0.75～2.50`、設備 `0.75～2.00` 的縮放值，並寫入存檔。

### 17.3 音效

- 放糧、吞食、擦玻璃、購買、出售、孵化、治療、寶箱、訪客小費與錯誤提示各有獨立音效。
- Phaser Sound Manager 必須在第一次使用者操作後才 unlock／resume；若 Web Audio 不可用，可退回無聲模式但不能阻止遊戲。
- 同類吞食音 100 ms 內最多播放一次；99 隻魚搶食不得疊成爆音。
- 設定保存 master、music、effects 三個 0～1 音量。
