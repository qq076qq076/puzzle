# 快樂水族箱：效能、安全與測試

> 用途：效能預算、安全邊界、測試、驗收與實作階段。
> [返回規格索引](../遊戲規格書.md)

## 22. 效能與穩定性

- 桌面 99 隻魚目標 60 FPS；中階手機目標 30 FPS。正式 benchmark 必須記錄瀏覽器、裝置／CPU、GPU、viewport 與 DPR，避免只報單一 FPS 數字。
- 99 隻魚時 `animal-ai` 平均 <4 ms/frame、Phaser render 平均 <8 ms/frame（基準 viewport 1000×600、DPR 2）；以連續 60 秒的 p95 frame time 同時驗收，不只看平均值。
- 鄰居查詢使用 spatial hash；粒子、食物、浮字使用 object pool。
- 同時粒子上限 300、浮字 30、泡泡 80；超過時重用最舊的非關鍵物件。
- DOM HUD 最高每秒更新 10 次，數值未變時不寫入 DOM。
- 圖片由 Phaser Loader 與 Texture Manager 載入、解碼與共用；不得另建平行的 DOM Image cache。動態魚群先使用一般 Sprite，只有 profiler 證明 Display List 成為瓶頸後才評估批次層，不能犧牲單魚互動與 depth 排序。
- 分頁隱藏時 pause Phaser Scene、Sound 與非必要 tween／粒子，保留必要存檔與雲端 flush；回到前景後只執行一次離線結算。
- 所有 Scene event、input、timer、tween 與 Sound 在 shutdown／destroy 時可完整清理，不得因 Scene restart 重複註冊。
- 每次正式建置記錄初始 JavaScript、首屏 texture 與完整 texture 的傳輸／解碼大小；超出前一版 15% 時須在變更說明中交代理由。

## 23. 錯誤處理與安全邊界

- 單機遊戲不宣稱防作弊，但所有載入資料仍須驗證，避免壞檔造成無限迴圈或 DOM 注入。
- 魚名與魚缿名最多 24 個 Unicode grapheme，顯示使用 `textContent`，不得插入 HTML。
- 交易與獎勵只接受設定表 ID，不接受任意價格從 DOM dataset 回傳。
- `Date.now()` 異常、圖片遺失、localStorage 滿、Firebase 失敗都必須降級可玩。
- 未捕捉錯誤顯示「遊戲遇到問題，進度已保留」面板，提供重新載入，不自動清檔。
- 「重新開始」需輸入魚缿名或連續二次確認，呼叫 `PuzzleSave.clear()` 後才建立新狀態。

## 24. 測試規格

### 24.1 單元測試

核心測試使用 Node.js 內建 `node:test`，直接匯入不依賴 Phaser／DOM 的 `src/core/`；測試不得啟動 renderer 才能計算交易或離線進度。

- 每個魚種的卵價、售價、解鎖、成長與飽食值符合本表。
- 第一顆教學孔雀魚卵只套用一次 60 秒 egg override；重開、重送任務或後續購卵不會再次取得教學加速。
- fry、juvenile、adult、亮鱗、生病的售價組合逐一斷言。
- 餘額不足或缺少持有物前置時交易不扣款、不建立物品；魚隻數量再多也不阻擋購卵。
- 同一 transactionId 執行兩次只成功一次。
- 基礎／進階餵食器不能同時占用 feeder 槽；替換後舊設備與剩餘設定仍在倉庫。
- 持有物解鎖在取得與失去最後一個前置物品後即時重算，已購買物品不因重新鎖定而消失。
- 清潔衰減、85% 上限、低水質倍率與 UV 防病正確。
- 飽食從正值到 0、生病 24h、死亡與復活的邊界時間正確。
- 繁殖名額預留、亮鱗機率路徑、可重現 RNG 與重整不重抽。
- 離線結算重跑不重複發獎，7 天、24 小時、3 寶箱上限正確。
- schema validation、未知 ID recovery、所有 migration fixture 通過。

### 24.2 動物 AI 測試

- 以固定 seed 模擬 10 分鐘，所有健康魚中心保持在合法水域。
- 任兩魚重疊超過 1 秒的比例低於 1%；99 隻壓力測試不產生 `NaN`。
- 魚糧 claim 不重複，一顆最多被吃一次。
- 點擊空白水域可連續放糧且沒有冷卻；放糧不直接增加飽食，只有碰到該顆魚糧的魚會回復。
- hunger、sick、dead 狀態的速度與深度符合規則。
- 魟魚不離開底層、龍魚不長時間離開上層、小蝦虎有停頓週期。
- heading 必須有 150 ms hysteresis，不得在低速時每 frame 翻面。
- 清潔生物 hungry 時不產生清潔效果。
- 清潔生物被動進食 10 分鐘節流、藻錠最低飽食 tie-break 與清道夫每日扣 1 顆皆可重跑；飽食 0 或長期離線只停工，不刪除實例。

### 24.3 整合與瀏覽器測試

- `pnpm build` 後以 Vite preview 或專案靜態伺服器測試產物，不能只測 dev server；控制台沒有 error，所有 runtime 資產 URL 在 GitHub Pages 子路徑下可載入。
- `BootScene → AquariumScene`、DOM shell 與 PuzzleSave 初始化順序正確；Scene restart 後 animation key、input listener 與交易 handler 各只有一份。
- WebGL 建立失敗時顯示可理解的 DOM 錯誤面板與支援資訊，不靜默切換到已 deprecated 的 Canvas renderer。
- 桌面、320 px 手機直向、橫向與 DPR 2 都可完成買卵、餵食、出售。
- 滑鼠與觸控的點擊／拖曳門檻不互相誤觸。
- 點擊魚、清潔生物、設備或藻斑不會同時在其下方誤放魚糧。
- 商店確認、防連點、面板 focus trap、Esc 與螢幕閱讀器標籤正確。
- 魚類 atlas、幫手／設備 strip 與裝飾單圖在桌面及 320 px 手機商店卡中皆完整顯示，沒有錯格、拉伸或容器裁切。
- 切換分頁 2 分鐘後回來，狀態只結算一次。
- 同瀏覽器同時開兩個分頁時只有取得 Web Lock／fallback lease 的分頁能初始化 PuzzleSave 與操作；關閉 leader 後 follower 可接手，且不倒退或重複結算。
- localStorage 與 Firebase 各跑一次新檔、續玩、雲端較新、清除存檔流程。
- 模擬 Firebase 回傳 `accepted: false` 時停止後續寫入、保存 recovery copy 並顯示衝突選項，不以本地狀態覆蓋較新雲端。
- 模擬素材載入失敗仍可操作，placeholder 不影響碰撞與點擊。

### 24.4 素材驗證

從 `games/happy-aquarium/` 每次改動素材後執行：

```powershell
./assets/tools/validate-assets.ps1
```

必須通過 87 張 runtime PNG、尺寸、RGBA、透明角、魚類圖集格位與 catalog classification 完整性驗證。

## 25. 驗收標準

- 玩家可以從新存檔一路完成買卵、孵化、點擊放糧、魚游近進食、成長、出售與依持有物再次解鎖購買的核心循環。
- 14 種魚與 3 種清潔生物的移動特徵可辨識，沒有越界、抖動或重複吃食。
- 商店所有表列價格、回收價與持有物解鎖正確；魚隻數量不設上限，交易不會重複扣款或發獎。
- 清潔、疾病、治療、死亡、復活、繁殖、訓練、訪客與寶箱可完成。
- 設備在線與離線都依排程、料倉與耗材運作。
- 關閉後再次開啟會顯示正確離線摘要，不因重整重複結算。
- 本機存檔永遠可用；Firebase 設定存在時可跨裝置恢復且較舊分頁不覆蓋新進度。
- 桌面與手機可完整操作，鍵盤、降低動態效果與 44 px 觸控目標符合規格。
- 單元、AI、存檔、素材與瀏覽器煙霧測試全部通過。

## 26. 建議實作階段

1. 基礎架構：Vite、Phaser 4.2.1、DOM shell、集中設定、素材 registry、PuzzleSave 與 Node 測試框架。
2. 核心養成：兩種新手魚、移動、餵食、成長、清潔、商店與出售。
3. 完整魚種：14 種魚、狀態圖集、疾病、死亡、復活與離線結算。
4. 中期系統：清潔生物、設備、耗材、繁殖與變種。
5. 長期內容：裝飾、訪客、表演、寶箱、任務與成就。
6. 完整驗收：production build、GitHub Pages 子路徑、行動裝置、可及性、效能、雲端同步、平衡模擬與錯誤降級。

每一階段都必須保持新存檔可玩、舊存檔可 migration、核心測試通過，不以最後階段一次補測。
